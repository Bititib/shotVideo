# 复刻双提示词写法与严格 JSON Schema

## 1. `framePrompt`（静态首帧生图提示词）规范

`framePrompt` 仅描述该镜头**开篇瞬间（`start` 时刻）的一张静止画面**，供下游文生图/图生图模型结合“人物与商品参考图”出图：

- **必含 5 层信息（按构图逻辑串写，中文自然语句）**：
  1. 景别与机位视角（参考 [camera-and-framing.md](camera-and-framing.md)）
  2. 在场主体身份（写清 `characters[].name` 及外观锚点、彼此站位关系、视线方向）
  3. 初始静态瞬间姿势/手部动作定格（写清定格态，如“双手正捏着信封边缘处于抬手半途”）
  4. 场景空间、前后景层次与色彩/材质细节
  5. 光照来源、色温对比与焦段质感
- **严禁出现的内容**：
  - 禁止时间演化与连续动词串：“然后转身离开”“接着举起手机”“逐渐变成”。
  - 禁止推拉摇移指令：“镜头缓缓推进”“环绕拍摄”（运镜写在 `videoPrompt`）。
  - 禁止空洞堆砌词：“8K超清”“大师级杰作”“赛博神作”“震撼视觉”。

## 2. `videoPrompt`（动态图生视频提示词）规范

`videoPrompt` 接收“已生成的定稿首帧”作为起点，描述从 `start` 到 `end` 的**增量变化**：

- **必含 4 要素**：
  1. 起始承接与动作轨迹（谁从首帧动作继续完成什么连贯运动，幅度大小）
  2. 与 `camera` 枚举严格一致的机位运镜轨迹（方向、速度感、是否始终保持主体居中或脱焦收尾）
  3. 次级动态细节（衣摆微动、雨水滑落、液体扩散、光线明暗推移、表情从疑惑转为笃定）
  4. 镜头结束前定格姿态/末帧落点，确保不破坏人物面部与商品外观结构一致。

## 3. 严格 JSON Schema（必须直接被后端 `JSON.parse` 与 `validatePlan` 接收）

最终输出**只能**是合法的单个 JSON 对象，不得包含 ` ```json ` 代码块、注释或额外解说文字：

```json
{
  "title": "字符串（<=150字，片名或主题短标题）",
  "duration": 15.0,
  "hook": "字符串（开场前3秒核心抓手与吸引机制）",
  "continuity": "字符串（全片统一画风、光源色温、人物服饰与空间连续性要求）",
  "characters": [
    {
      "id": "role_1",
      "kind": "person",
      "name": "人物或核心商品名",
      "appearance": "客观视觉外貌/材质包装锚点描述"
    }
  ],
  "shots": [
    {
      "id": "01",
      "start": 0,
      "end": 3.0,
      "title": "镜头功能标题",
      "characters": ["role_1"],
      "scene": "雨夜 · 木门廊下 · 暖黄壁灯",
      "action": "纯文本舞台动作描写（不含机位术语）",
      "speaker": "角色名 / 旁白 / 无对白",
      "audio": "雨声、轻微布料摩擦声、低沉大提琴铺底",
      "camera": "push_in",
      "framePrompt": "纯静态首帧描述（景别+机位+人物位置与定格姿势+环境+光影）",
      "videoPrompt": "承接首帧后的动作演变+平稳推近运镜+环境微动+末态定格",
      "caption": "精确台词/字幕，无则空字符串"
    }
  ]
}
```

## 4. `camera` 与 `kind` 允许值白名单

- `characters[].kind` 仅允许：`"person"` 或 `"product"`。
- `shots[].camera` 仅允许：`"auto"`, `"static"`, `"push_in"`, `"pull_out"`, `"pan_left"`, `"pan_right"`, `"tilt_up"`, `"tilt_down"`, `"orbit"`, `"follow"`, `"handheld"`, `"dolly_zoom"`。
- 所有文本字段长度不超过 `2400` 字符（`title` 不超过 `150` 字符，`name` 不超过 `100` 字符）。
