## 实际变更与调用链

原公开 API 入口继续使用 `gemini-omni-flash`，内部销售记录 `funai-gemini-omni-flash` 不变；仅当前渠道执行型号切换为 `omniomni-flash-1.1`。因此调用方不用换模型名，管理员已设置的售价、开关、限制和手动其他型号覆盖不会被重置。

1. 启动时 `initDatabase` 调用一次性配置迁移：同一事务更新该渠道旧映射及规格路由的旧上游 ID。不改订单、已受理编号、账本和密钥；不改其他供应商；再次启动不覆盖迁移后的人工配置。
2. 渠道同步将新 ID 归到原销售入口。新旧 ID 同时出现时只保留一个销售项；只出现旧 ID 时不回退，返回明确的目录授权提示，并由既有可用性校验阻止该线路执行。新建销售项仍默认停用。
3. 网站 `/api/video/generate`、外部 `/v1/videos` 及批量内部桥接均调用 `handleSpecificationGeneration` → 规格路由 → `submitSpecificationVideo` → 当前渠道适配器。调用中实际发送新 ID，并保存受理编号后查询。
4. 已受理历史任务仍由 `resumeSpecificationTasks` / 原任务恢复逻辑使用原渠道、原身份、原任务 ID 查询；配置迁移不把历史记录改成新型号，不再次生成或扣款。
5. 失败任务仍按原 ID 查询，显式携带相同 `Idempotency-Key` 时返回原幂等记录，换型号不会偷偷重新生成。2026-11-04 调整无键调用约定后，不传该请求头的每次 POST 都新建任务并分别计费；不重新执行旧订单。
