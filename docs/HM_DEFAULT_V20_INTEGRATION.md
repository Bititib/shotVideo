## 协议与规格依据

- 模型选择器的 `data-sku` 明确为 `default:vid:MINIMAXH3-2.0采样` 和 `default:vid:MINIMAX-H3-2.0采样-933`。名称拼写不同，不能统一补连字符。
- 两者均显示 4–10 秒、720p。基础版支持首尾帧、多帧、混合素材；933 仅支持多帧、混合素材。
- 比例选择器提供 21:9、16:9、4:3、1:1、3:4、9:16。
- 基础版混合素材界面提示 30 图 / 3 视频 / 3 音频。933 继续使用已确认的 9/3/3；上游普通素材提示在切换 933 后仍显示通用的 30/3/3，与型号数字约定冲突，不据此扩大 933 上限。
- 多帧 UI 的通用提示为 20 个图片或视频，但 API 文档明确至少 2、最多 10 个图片关键帧。因此本站显式 multi_frame 使用 2–10 张图片（还受型号总图片上限约束）；视频和音频须用 omni_reference，不能静默丢弃。
- 普通参考素材使用 JSON `materials`，保留所有素材和名称标记；明确首尾帧仅基础版可用。933 包括纯文本在内显式使用 omni_reference，避免上游自动回落到不支持的首尾帧模式。
- 沿用 POST /v1/videos/generations JSON、HTTP 202 task_id、GET /v1/tasks/{task_id} 的已有 HM 协议。没有增加提示词字数硬限制。
- 文档中的渠道维护说明和当前模型广场展示并不完全一致；保留现有渠道地址、密钥、开关，不宣称真实线路可生成。未执行付费生成。

## 实际调用链

1. shared/hmStudioVideo.ts 统一映射、售价默认值和规格；seed.ts 与 hmStudioCatalogService.ts 读取它注册/同步，现有价格不覆盖。
2. 网站 video.ts、外部 API v1.ts、批量 validate/quote 共同校验时长、分辨率、素材和独立帧，在预扣前拒绝不支持的输入。外部 API 额外校验显式 function_mode。
3. 共享队列 enqueueHmStudioVideoContent 经 hmStudioAdapter.ts 固定 channel=default。适配器再校验一次，以覆盖历史排队参数。
4. 规格路由 specificationAdapters.ts 按真实上游映射模型校验，而非只覆盖 nova。
5. 原有 HM 任务 ID 持久化、独立回执、恢复查询、结算与退款路径继续复用；未修改其它上游的业务状态解析。
6. 视频页、批量页、规格预设从共享定义读限制；分镜工作室及画布参考素材限制同步接入。

## 验证范围

隔离内存数据库及模拟上游，不触碰生产订单或余额：
- 基础版禁用时禁止预扣；启用后的 web/API 实际发送 model/channel、完整参考素材及明确拒绝退款。
- 两者时长、分辨率、素材数量越界在扣费前拦截；933 独立帧/首尾帧模式拒绝；多帧不丢视频音频。
- 批量报价、预扣、重复提交与取消退款幂等；管理员定价同步和重启后保持。
- 真实 HM 队列的明确拒绝只退款一次、502 未知受理不重发、任务 ID 先存再查、临时查询失败后恢复成功且不重复扣费。
- nova/lumen、规格路由及相关批量/恢复/JSON 回归测试；TypeScript 检查、生产构建。
