# miniKey 接入记录

2026-11-11。实现位于独立工作区 `scratch/minikey-integration`，分支 `codex/minikey-integration`，基于 origin/main `982606c`。原目录与 `scratch/huss-final-publish` 的未提交改动未被覆盖。

## 协议与范围

官方依据：[接口文档](https://minikey.work/studio.php?page=docs)、[完整协议](https://minikey.work/openapi_md.php)、[公开模型目录](https://minikey.work/openapi/v1/models)。

视频、图片和音乐分别解析协议。有效任务 ID 先持久化；明确拒绝或任务明确失败才退款；查询、下载异常保留原任务继续处理。图片和音乐的未知受理不会重发生成。错误保存阶段、HTTP 状态、上游错误码及具体原因，并脱敏。

## 后台配置

渠道管理 → 添加 miniKey 渠道 → 模型与参数 → 添加模型。本站模型 ID 与上游型号分开保存，无渠道前缀。读取当前目录选择型号与线路，配置保存到实际调用所用的模型注册和渠道映射。

新模型默认停用；在关联模型中配置售价并启用，不覆盖既有定价。音乐需要按次售价，并在等级配置开放“音乐生成”和相应模型权限。音乐原有草稿重新保存即可注册为可执行模型；不会自动开启旧草稿。

视频固定选择上游线路、秒数、清晰度及素材限制。图片支持 Banana 比例/清晰度格式和 image-2 像素尺寸/质量格式；后者目前限 1K。相同协议的新型号可直接后台添加，协议不同的新类型仍需新增适配。

编辑具有版本冲突检查、请求预览、未保存修改保护；同步目录不擅自添加或启用模型。

## 实际调用链

- 视频/图片：网站、外部 API、视频批量队列进入 `handleSpecificationGeneration`，通过规格路由调用 miniKey 适配器。复用原订单预扣、结算及恢复。视频保存提交标识、凭据指纹、即时终态与成功回执；图片保存各张任务编号与凭据指纹，恢复原任务和已有结果。下载视频仅向原任务文件端点发送密钥。
- 音乐网站：`/app/music`；后台模型列表、描述/歌词/模式/人声/标签、明确价格、任务列表、音频播放和 MP3 下载。提交前在浏览器保存原请求与编号，超时或刷新后可以原样核实。
- 音乐外部 API：`POST /v1/music` 创建；`GET /v1/music` 列表；`GET /v1/music/{id}` 查询；`GET /v1/music/{id}/file` 下载。使用同一 API Key，任务按 Key 隔离。API 模型目录、调用示例和接口文档已加入音乐。
- 音乐服务：订单和预扣、请求编号及上游参数在同一事务保存；持久化租约控制提交；先记录发送阶段，再调用上游；收到编号立即保存。生产入口启动每 8 秒恢复扫描，重启后只查询已受理原任务，提交中断而没有编号的订单保留核实。
- 音乐结算：网站个人/组织余额、API Key 额度及关联账户原路退款；终态与资金事务提交，重复恢复不会再扣退费。上游复用同一任务编号时，新重复订单退费，不重复计费。人工结算后停止自动处理。
- 音乐文件：通过原任务文件接口取回 MP3，跨站重定向不携带密钥，验证文件标识、限制 100 MB、原子保存；成功回执保留，下载中断可独立恢复。仍在生成/核实的记录不能删除。
