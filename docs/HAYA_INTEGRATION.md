## 启用

1. 重启更新后的服务，初始化逻辑会注册这八个模型及其初始价格。新增的 `Seedance-2.0-720` 默认停用；已有价格、名称和启用状态保留。
2. 后台渠道管理新增渠道，类型选择 **Haya AI**，Base URL 填写 `https://hayaai.fun`（也兼容末尾 `/v1`）。在服务端后台填写 API Key；不要放进浏览器配置或提交到仓库。
3. 新建渠道时自动绑定已适配模型，随后点击模型同步。现有渠道通过同步添加新型号。同步通过 `GET /v1/models` 取已适配模型与当前可用列表的交集，不导入文本或其他未适配模型；下架模型不再接受新提交，已有任务仍使用原渠道查询。XG 2.0 同步时补齐缺失的 ¥4/次默认规则，不覆盖管理员已有定价。
4. 检查后台模型启用状态、计费和用户等级权限，在视频页选择模型：`Seedance-2.0-720` 位于 Seedance 系列，其余 Haya 型号仍在 Haya AI 分组。后续模型可用性变化时再次同步渠道。展示分组不改变底层 Haya 调用渠道。
5. 用一条短任务验证素材上传、进度、成品播放和费用，然后再开启批量任务。真实生成会产生上游费用。

## 素材与参数

- 旧七款提供 4–30 秒整数时长，分辨率固定为对应型号；Y 截图仅注明自由时长，4–30 秒是本次应用侧支持范围，并非供应商全量能力承诺。XG 2.0 的独立限制见下节。
- BZ 截图确认最多 30 张图片、10 个视频、10 段音频。Y 三款确认 30 张图片、0 个视频、10 段音频。
- F、XG 2.5 截图没有给出素材上限；目前应用接收上限为 30/10/10，实际支持类型、数量、比例仍须向供应商核对，不能把此上限理解为已确认的上游能力。
- 当前主线已将本地素材和本站 `/uploads/` 素材发布为本站公开素材链接，不再调用上游 `/v1/files`。外部公网 HTTPS 文件直链直接传递，完整保留签名参数，不由本站任意抓取外部地址。
- 单个本地文件不超过 20 MiB；图片宽高各在 300–6000 像素。外部直链的内容、大小和尺寸由上游校验。
- 旧七款创建任务使用 JSON 的 `images`、`videos`、`audios`；XG 2.0 使用根级 `content`。不向视频创建接口直接发送 multipart 文件，不透传 Base64 或本站相对路径。
- 当前七款发送 `seconds`、`ratio`、`resolution`。首尾帧专用字段未在通用协议定义，明确拒绝；对外 API 拒绝同时传 `size`，避免尺寸冲突。
- 对外 API 支持通过 `metadata` 对象传递模型公开扩展参数。

## Seedance-2.0-720（2026-10-27 更新）

证据：用户提供的模型卡片，以及当日读取的 [Haya 模型广场](https://hayaai.fun/pricing) → 搜索精确型号 → 详情 → API。`openai` 与 `openai-video` 页签显示相同的型号专属示例。

卡片写 4–15 秒、9图/3视频/3音频、全比例、¥3/次；但该型号 API 页签写 5–15 秒、不支持视频参考、六种比例，示例文字还保留 ¥2.8/次。2026-10-27 用户提供《hayaai-通用接入文档-最新版》（正文日期 2026-10-25），并明确确认此接口支持该型号的 9图/3视频/3音频。按此确认修正视频上限和生成参数，不再沿用网页的禁用视频限制；时长和比例仍按专属 API 页签。本站初始售价由用户另行确认 **¥4/次**，不依赖上游文字推算或动态改价。

证据边界：通用文档明确 `/v1/files` 上传和 `/v1/videos` 提交流程，但未列出该型号的视频字段。实现沿用该型号根级 `content` 的素材结构，为视频加入 `video_url` 项；这是基于用户确认和现有素材结构的实现选择，并非通用文档中已有该型号的成功请求示例。已用模拟上游核对实际发送内容，尚未通过真实付费调用验证上游接受及参考效果。现有素材服务继续提供公网直链，外部已上传的签名 URL 原样保留。

- 按用户要求，对外 ID 和默认显示名称为 `Seedance-2.0-720`，不带 `XG-`。内部仍映射到精确上游 ID `XG-Seedance-2.0-720`，保留大小写。初始化、渠道默认映射和上游模型同步均使用此映射，不将上游前缀重新导入公开目录；旧 `XG-seedance-2.5-720` 不替换、不改价。此前带前缀的新型号版本仅在隔离目录开发，未部署，不涉及生产历史模型迁移。
- 固定 720p，5–15 秒整数；对外 API 未传时长时默认 5 秒，上游 `seconds` 使用字符串。

### 实际执行路径与验证

- 网站、画布：`server/routes/video.ts` 校验/预扣/保存订单 → `submitHayaVideo` → 保存 `videoId` → 查询和保存结果；批量队列通过 `videoBatchService.dispatch` 调用相同入口，用批量账本结算。
- 外部 API：`server/routes/v1.ts` 解析参数和 content → 校验/预扣/保存订单 → 相同 Haya 适配器 → 原任务轮询。默认 5 秒和素材转换均有入口测试。
- 规格路由：`specificationAdapters.submitSpecificationVideo` 改为使用 Haya 独立提交逻辑，不再将通用 `request_id` 当作任务 ID；`specificationGenerationService` 持久化原任务并结算。明确拒绝传递到退款路径，未知受理不切线路、不重发。
- 模型列表、报价、开发者模型参数、画布和规格预设共用型号限制。新模型初始化和同步默认停用；管理员改价/启用后再次初始化或同步保持原值。
- 模拟测试覆盖网站/API 成功、参数拒绝、批量成功与拒绝退款一次、批量提交未知保留资金且不重发，以及实际规格服务的相同边界和仅有 request_id 的响应。旧 Haya 和其他路由回归一并运行。
- 2026-10-27 视频参考回归：网站/API 别名参数、API 根级 content 和真实批量调度均同时传入 9图/3视频/3音频，断言全部 15 项及签名参数到达上游请求；规格执行覆盖 3 个视频。4 个视频在提交/扣费前拒绝，Y 型号禁用视频的规则保持不变。
- 本次验证结果：13 个测试文件、282 项测试通过；TypeScript 检查通过；Vite 生产构建通过（使用隔离目录内的临时路径解决 Windows 临时文件权限问题，存在既有大资源包提示）。本次基线为 GitHub main `6484661`，开发目录 `scratch/haya-xg-seedance-2-720`，未覆盖旧工作区。
- 未验证范围：真实上游任务、线上启用、部署，以及所有历史 Haya 错误码/状态的完备性；此次不宣称修复所有 Haya 待核实情况。

## 状态和费用

创建前保存本地记录并预扣费用。只有准备开始视频创建 POST 时，才持久化 `hayaSubmissionStarted`；创建请求不自动重试。上传失败和明确的创建拒绝可以退款。创建网络异常、408、5xx、响应损坏或缺失公开任务 ID 时标记为 `review`，保留预扣费用，禁止自动重提或跨渠道补发。

正常轮询为 12 秒，查询异常按 24、48、60 秒退避。状态 `queued` 和 `in_progress` 不因进度停滞或超过旧的 30 分钟恢复超时而判失败；只有任务明确 `failed` 才结算失败。`completed` 后先保存视频到本站，再向用户交付。

保存完整 `metadata.url`，签名链接不携带 API Key；签名链接失效时可尝试带鉴权的 `/content` 接口。下载失败继续查询和保存原结果，不重新生成。

服务重启后：已保存 task ID 的任务继续查原任务；已开始创建但缺失 ID 的任务进入待核实。管理员需使用 request ID、提交时间和 Haya 后台记录核实。文档未提供任务搜索、幂等创建或按业务 ID 找回接口，因此不能自动找回没有保存 task ID 的任务。核实后需补齐原任务 ID 再恢复，或确认未创建后退款；不能直接点击重试创建新任务。

待核实记录有原任务 ID 时，可使用已有管理端任务恢复功能查询。已预扣且未退款的 Haya 任务恢复成功不再次扣费；上游确认失败时原路退款。
