# 纵横科技仅使用 V6K 视频接口

## 2026-10-27 回执与查询修复

依据当前公开视频 OpenAPI 1.2.0：<https://www.v6k.top/docs/openapi-video.json>。其中 Video.status 包含 `unknown`；页面简表只列四个状态时，以 OpenAPI 的五种状态兼容处理。文档地址：<https://www.v6k.top/docs?guide=unified&category=video>。

- 网站（含批量调用）、外部 API、销售规格路由取得非空、有效字符串 `id` 后，先持久化原任务编号、渠道和 Key 标识，再处理 HTTP 状态、业务状态和即时终态。不把编号转为数字；状态缺失、未来新状态或冲突的 HTTP 错误均不丢弃有效编号，保留诊断并查询原任务。非 JSON、仅有请求追踪号或未确认的编号结构不能伪造生成回执。
- 回执表先独立保存，后续内容元数据写失败不丢失已有回执。提交占用继续阻止重复 POST；规格路由发送前也保存业务订单号。请求头 `Idempotency-Key` 仅作关联，不假定上游承诺去重，不自动重放结果未知的生成请求。
- `unknown` 是非终态，保留原任务、显示状态待确定，继续查询；不据此退款或切换线路。仅 `completed`/`failed` 进入原有幂等结算。成功仍通过鉴权 `/content` 保存原结果，不重复生成。
- 各入口和重启恢复使用同一查询响应解析及退避规则：正常间隔 20 秒；连续异常 20/40/80/120 秒；`Retry-After` 更长时按上游要求等待。HTTP 错误、非 JSON、任务 ID 不匹配和网络异常均不视为任务失败。规格路由也使用覆盖响应体的硬超时，避免无限等待。
- 有效查询后重置失败计数。规格任务一轮两小时查询结束后保留 processing 和下一次查询时间，由后台扫描接续；不会因为单轮时限自动变成人工核实。历史没有有效 ID 的待核实记录不能从新版本凭空恢复编号，仍需原回执或管理员核对。

验证覆盖：实际网站与 API 入口、真实规格执行与隔离预扣账本、持久化回执失败、重启扫描并发、挂起查询硬超时、429/5xx/非 JSON/unknown 后成功或失败、明确拒绝不误入核实、重复恢复只扣退一次；同时运行批量桥接/账本与其他渠道回归测试。未进行真实付费生成、生产退款或 VPS 部署。本次不推测未确认的像素尺寸，也不静默修改旧型号参数。

本次验证结果：相关 20 个测试文件、482 项测试通过；`tsc --noEmit` 与生产构建通过。构建仅有已有的动态导入及较大分包提示。

旧的视频协议已移除，不再调用旧站提交、/v1/tasks 查询或 /v1/media 上传。

## 上线配置

1. 更新启动后，原纵横渠道统一为 V6K 类型。使用旧站地址的渠道自动改为 https://www.v6k.top 并暂时停用，避免将旧站密钥当作新站凭据使用。
2. 首次启动会归档并移除旧站模型、旧站售价、模型映射与旧销售线路。历史任务、余额、账单、成品文件不变。归档位于数据库内部的 v6k_retired_configuration，不出现在模型管理中；迁移仅执行一次。
3. 后台编辑原渠道，填入 V6K 站点创建的新令牌，测试连接并同步模型，核对精确模型 ID、时长、分辨率及售价后启用。
   同步以携带令牌的 /v1/models 为权限依据，结合新站公开 /api/pricing 的视频端点分类；不会仅凭名称猜测视频模型，不会从公开目录导入当前令牌无权使用的模型。
   新模型默认停用，不创建旧站默认价格，也不把上游价格自动作为本站售价。已设置的新站价格和启用状态在后续同步、重启时保留。
4. 如模型使用销售路由，核对线路所用渠道 ID。原渠道记录 ID 保留，不需要重建账单或删除历史记录。
5. BACKEND_URL 使用本站公网 HTTPS 地址，确保 /reference-assets/ 可由上游读取。参考素材使用随机名称的稳定文件链接。

## 新任务

- POST /v1/videos，使用 seconds/images/videos/audios，保存返回的 id。
- GET /v1/videos/{id}，识别 queued/in_progress/completed/failed，通常每 20 秒查询，临时错误退避并尊重 Retry-After。
- GET /v1/videos/{id}/content，由服务器携带新站令牌下载并保存；浏览器和其他下载域名不会收到令牌。
- 明确提交拒绝或任务失败只退款一次；查询和下载错误继续处理原任务。504、断网或缺少 ID 且接单结果不明时待核实，禁止自动重提。
- 文档未确认首尾帧、quality、negative_prompt、generate_audio；这些选项会在生成前明确报错。

文档：https://www.v6k.top/docs?guide=unified&category=video
