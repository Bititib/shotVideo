# 模型规格与渠道分流

管理入口：后台 → 模型规格与线路（`/admin/model-routing`）。

## 入口划分

图片按“模型 + 输出分辨率”划分，例如 GPT Image 2 · 1K、GPT Image 2 · 2K、GPT Image 2 · 4K。参考图支持 10 张还是 16 张只属于线路能力，不再各自生成入口。图片页和画布随所选入口固定输出分辨率。

视频保留原售卖模型的显示名称、API ID、计费规则和时长规则。草稿仅合并声明支持同一个 API ID 的渠道，不再按名称、输入数量或分辨率推断两个售卖模型相同；固定 30 秒、4–30 秒任选以及按条、按秒的原入口分别保留。管理员可显式关联经确认可替代的执行线路，用户仍按当前入口的售价付费。

## 管理步骤

1. 点击“添加规格”，从已有接入载入能力和线路草稿。草稿来自项目中已确认的适配器能力；未知能力不会当成无限支持。
2. 检查公开 API 模型 ID、显示名称、参考素材数量、分辨率、比例、时长规则和首尾帧。图片入口必须固定一个输出分辨率；保存后的所属模型、分辨率及 API ID 保持稳定。`900` 表示最多 9 图、0 视频、0 音频，`301010` 表示最多 30 图、10 视频、10 音频。
3. 检查“合并已有重复入口”。视频合并必须具备独立且相同的用户售价、计费单位及已知服务能力；否则保存时拒绝合并。若历史关联后来因定价变化不再兼容，目录恢复旧入口，旧 ID、旧名称继续采用自己的售价；后台提示解除不兼容的关联，不自动重写已有配置。图片仍沿用按分辨率的旧 ID 兼容方式。
4. 展开关联线路，核对渠道、执行模型、上游模型 ID，以及每条线路的真实能力。视频新草稿的上游单位默认为“待确认”；确认按条或按秒后再填写第三方真实成本。用户售价与上游成本分别展示，不能从用户售价推测上游单位；修改线路不修改用户售价，价格管理链接直接定位当前 API ID。
5. 保存后生效。新建公开 ID 必须另行配置用户售价，并核对用户等级权限。现有历史配置不会在启动时被自动改写。
6. 使用“模拟选路”查看匹配结果、排除原因及预计上游成本。模拟读取已保存配置，不调用第三方，也不产生费用。

列表可按渠道筛选，能从规格查看所有关联渠道，也能查一个渠道参与了哪些规格。规格、模型、渠道、Key、单条模型线路的禁用开关都会参与判断；恢复健康状态不会打开手动关闭的开关。

## 选路规则

例如用户选择 GPT Image 2 · 2K，提交 12 张参考图，只选择支持 2K 且至少支持 12 张参考图的线路；只支持 10 张的线路被排除。

先检查公开规格，再检查每条线路：数量上限、最少图片、输出数量、分辨率、比例、质量档位、独立首尾帧及视频时长。范围时长可设置步长，例如 4–30 秒、步长 1，15 秒可用；固定 30 秒线路不匹配 15 秒。

符合参数且健康的线路按本次请求实际成本排序。按秒成本乘实际时长；图片逐张请求，成本乘张数。分辨率单独成本覆盖基础成本。单位待确认或金额未填写都属于未知成本，排在已知成本之后，同成本按备用顺序、渠道优先级排序。

同一渠道不同时长结算价格不同，可添加多条关联并分别设置固定时长或不重叠的时长范围、对应成本，继续使用现有参数匹配机制。只确认 5 秒和 10 秒价格时，不把它们推断成所有时长同价；公开范围中没有匹配线路的请求会明确拒绝。不同固定时长用户售价的服务保留各自售卖入口，自定义价格备注不会自动变成时长阶梯价。

前端的图片页、视频页、画布和批量视频读取公开规格能力。服务端始终重新校验；不会通过截断素材让不兼容线路接单。队列出队及切换线路时会再次检查手动开关。

## 故障、恢复与费用

- 上游明确拒绝受理的鉴权、余额、限流、容量错误，可改走下一条匹配线路。
- 已返回任务 ID 后固定查询原渠道和原 Key；普通查询异常不会重新生成。
- 提交超时、无法确认是否受理、响应无法解析，保留任务与预扣进入待核实，避免重复生成和扣费。
- 普通线路故障进入冷却，30 秒起逐次增加，最长 15 分钟。冷却结束只允许一个请求试用，成功恢复，失败继续冷却。
- 无效 Key、鉴权或余额错误进入阻止状态，管理员处理后点击“恢复检测”。此操作仅重置健康状态。
- 图片与视频均使用预扣凭据，切换线路不会重复扣费。确认失败退款；多张图片按成功张数结算。已受理任务重启后只恢复原任务查询和保存，不自动补发。
- 图片结果与视频结果保存到本站；内部渠道、Key、选路尝试和上游成本不出现在普通用户内容记录中。

## 视频费用预估

普通视频页和画布调用 `POST /api/video/quote`，按当前售卖 API ID、分辨率和时长返回用户单价、计费单位与本次总价。接口只读取报价，不上传素材、不调用上游、不预扣。参数变更立即隐藏旧报价；较晚返回的旧请求不会覆盖新报价。批量视频继续采用原有后台校验及报价流程。

浏览器提交携带 `expectedCost`，服务端在预扣前与当前售价重新比较；发生变化返回“售价已更新”，不创建托管任务或扣费。未携带该字段的原 API 调用保持兼容。此预估是对外售价，不是渠道成本；故障切换不会重新定价或重复扣费。

## API 调用

API 使用后台的稳定“API 模型 ID”，不依赖可以修改的显示名称。例如配置 ID 为 `seedance-2.5-900`，请求中的 `model` 填该 ID。图片示例 ID 为 `gpt-image-2-1k`、`gpt-image-2-2k`、`gpt-image-2-4k`。实际可用 ID 从 `/v1/models` 获取。

已关联的旧图片 ID 根据 `resolution` 或 `output_resolution` 选择同一模型的分辨率规格。旧 GPT Image 2（Pidoi）未传分辨率时沿用原有质量默认值：`quality=low` 为 1K，其他为 4K；四月天和鸣飞旧入口默认 2K。请求的分辨率尚未开放时返回明确错误，不改用另一分辨率。直接传固定规格 ID 时，不允许请求其他分辨率。

图片调用 `/v1/images/generations` 或 `/v1/images/edits`，视频调用 `/v1/videos`。参考素材兼容站内字段与原有 API 字段；同一种素材不要同时使用两个别名字段。图片及首尾帧继续经过本站素材校验。

视频立即返回本站 `task_...` ID，通过返回的 `status_url` 查询。图片如提交结果仍待核实，返回 HTTP 202 与记录 ID，避免把未知结果当作可重试失败。

未配置统一规格的模型继续采用原有路径。已有渠道协议适配器被复用；新增第三方渠道仍需先完成协议接入及能力核对。

## 验证范围

单元及集成验证使用隔离内存数据库和模拟上游，涵盖参数匹配、成本比较、禁用、故障恢复、事务回滚、单次预扣、图片恢复及后台操作。前端完成类型检查和生产构建。真实上游可用性仍由运行时响应和健康状态决定；本次未进行付费生成或部署。
