## 实际执行链

- 管理员路由 `/api/admin/model-specifications/kkseadanco2.5/kk-routing` 受 `admin.ts` 的登录与管理员中间件保护。GET 只返回脱敏渠道、配置版本；POST 先用选中渠道令牌只读查询 `/v1/models`，再校验版本和渠道未变化，在同一事务保存规格及关联。需要的型号缺失时完全不写入。模型存在于目录不等于真实生成鉴权已通过。
- 网站与外部 API 的 `handleSpecificationGeneration`、持久化批量桥接共用 `selectModelRoutes` 与 `runVideo`。报价快照、订单、预扣、逻辑请求 ID 先保存，再进行占用和提交；保留原 API 幂等请求绑定。后台配置不修改历史订单/任务 ID/账本/余额/价格。
- 明确不可用且未发送的线路可跳过。已发送的请求只在连接建立前失败，或得到无任何受理证据的结构化 HTTP 429 错误时允许下一线路。纯 HTML 429、401、参数错误不触发 KK 自动切换；5xx、超时、未知受理均不重发。429 同时带有效 ID 或受理状态时保留原受理证据。此规则仅扩展 KK 两条内部线路，其他渠道沿用原策略。
- 两次安全线路尝试使用同一逻辑请求 ID、同一网站订单和预扣；不把生成接口收到幂等请求头当作上游具有去重保证。绝不重放结果未知的生成 POST。上一线路明确拒绝后的占用释放，下一线路重新取得占用；取得 ID 后立即持久化原渠道/编号，再解析终态或查询。
- `pollVideo`、`resumeSpecificationTasks` 和现有 V6K 恢复机制查询已保存的原渠道、凭据与任务 ID。保存结果和结算继续原账本。分流按钮不取消、重提或退款已受理任务；已接单后失败只走原失败结算，不自动再次生成。
- 稳定型号纳入 V6K 允许关联的范围；后续用户要求新增的独立入口为 `wd-seedance2.5-720`。它与 KK 的首选、分流开关、价格和模型/规格开关分别保存；同步不自动改变 KK 配置，重启关联清理保留已接入线路。

## 后台只下载原视频

对于缺少任务编号的 V6K 单条规格订单，管理员可在失败、待核实订单详情选择「只下载原视频」。填写 V6K 已核对属于原订单的完整任务编号。服务端使用订单保存的接口地址和渠道，只读查询该编号，核对任务 ID、实际模型、已完成状态及本站回执冲突，再通过固定成品接口下载。编号归属仍须按上游原始请求核实，单靠时间和型号无法确认。下载不绑定编号，不调用生成、结算或恢复订单接口。已退款的订单也可仅下载成品。

## 后台补录并恢复到订单

后台视频详情的「原视频恢复」适用于各渠道的失败或待核实订单。已有原任务 ID 时可以直接恢复，缺少编号时填入上游核实过的编号。服务端复用原渠道的查询和成品下载协议。下载完整后再次核对订单和回执归属，在同一事务保存回执与本地成品路径，将订单标记为完成。历史订单元数据中的任务编号也参与冲突检查。相同订单和编号重复恢复时返回已保存的结果。

恢复仅写入任务与成品记录。原金额、余额、预扣和退款记录照旧，已退款的订单可以恢复原视频。批量订单只恢复当前子任务，批次结果与订单同一事务更新。若原渠道或执行密钥缺失、后台仍在处理、上游未完成、成品已失效或编号属于另一订单，恢复停止。旧版按账务规则执行的批量恢复入口有单独的操作提示。
