# TT 的 BB 备用线路

## 型号与协议依据

- 主入口保持 TT 480P、720P 的现有 ID 和管理员售价，不新增前台 BB 产品。1080P 没有本次对应备用。
- 内部备用精确 ID 为用户截图指定的 `BBseadanco-480`、`BBseadanco-720`。用户确认两条都需要视频参考：30 图、10 视频、10 音频，5–30 整数秒，各自固定 480p/720p。截图上游成本分别为 0.25/0.35 元/秒；这些是线路成本，不覆盖 TT 售价。
- 2026-11-02 阅读 [V6K 统一视频文档](https://www.v6k.top/docs?guide=unified&category=video)：POST `/v1/videos`；JSON 的 `model`、`prompt`、`seconds`、`ratio`、`resolution`、`images`、`videos`、`audios`；保存字符串 `id` 后 GET `/v1/videos/{id}` 查询、GET `/content` 下载。
- 当天公开目录列出 `BBseadanco-720`，但 480P 列出的是 **`BBseadanco2.5-480`，注明不支持参考视频**。不能替代用户要求的型号。本次不导入该不同型号；只有生产 Key 的鉴权 `/v1/models` 确实返回 `BBseadanco-480` 才绑定该备用。未拿到此授权目录或未做付费验证，不代表 480P 实际调用已通过。

## 后台操作

更新服务后，在纵横 V6K 渠道点“同步模型”。已授权的精确 BB 型号会绑定到对应 TT 的销售规格中；新增备用线路默认关闭，重复同步保留管理员开关、成本和原路由。

进入“模型路由”，打开 TT 480P 或 TT 720P 的“管理线路”，找到带“BB 备用”的线路，开启“启用这条模型线路”并点“保存规格与线路”。关闭任一备用只影响新请求，已接单的任务继续查询原任务。

若没有出现某条备用，表示当前 Key 尚未返回该精确型号，请先核对上游授权和型号；不要把不支持视频的其他 BB 型号手动改成它。

## 提交与计费顺序

1. 网站、外部 API、批次/画布沿用现有 TT 规格入口和一次预扣；原销售价格、权限和请求去重机制不变。
2. 参数匹配后 TT 排在 BB 前面，BB 即使填写更低成本或优先级也不会抢先。
3. 已核实的当前 Key 目录没有 TT、有对应 BB，或 TT 主线路手动关闭时，使用已开启且授权有效的同分辨率备用。目录证明与渠道地址、Key 绑定；换 Key 后需重新同步才能使用 BB。空目录不改变此前证据。
4. TT 提交明确被 401/403/429 拒绝且无任何受理编号，或可证明连接尚未建立，允许尝试下一条线路；同一订单继续使用原预扣。其他参数错误直接结束，不能通过改素材或规格掩盖错误。
5. TT 已有任务 ID（包括立即失败、unknown 或带冲突错误的 ID）、提交超时、断线、503/504 等受理不明，不会发送 BB。查询/保存失败也不会触发重新生成。
6. BB 接单立即持久化真实任务 ID、原渠道和执行型号。之后即使管理员关闭 BB 或目录变动，继续恢复该任务；确定失败由原幂等账本退款一次。BB 响应不明保留原预扣，不能用上一条 TT 的拒绝给 BB 退款。

鉴权目录核实不生成任务；未在生产环境调用付费生成接口。模拟验证覆盖同步开关、优先顺序、同分辨率匹配、视频/音频保留、网站/API/批次切换、重试去重、失败退款、未知受理不退款和原任务恢复。

验证结果：最终相关七个测试文件共 358 项全部通过。类型检查、生产构建通过；未运行本次全量测试，未做生产部署或真实付费生成验证。
