# 四月天 MiniMax H3 2K

## 依据与范围

2026-10-29 用户提供四月天模型截图，并确认“2r一条/其他参数接口一样的”。本次沿用该渠道现有 `/v1/videos` 异步协议；没有把其他供应商的 MiniMax 模型名称或价格映射过来。

- 对外及上游模型：`minimax-h3-2k`。
- 本站默认售价：¥2/条；截图上游成本：¥1/次。
- 固定 2K、有声、4–15 秒整数时长。
- 比例：16:9、9:16、1:1、4:3、3:4、21:9。传图片时按图片比例，提交不再附带冲突的比例。
- 参考素材最多 9 图片、3 视频、3 音频；首尾帧与任何参考素材互斥。

协议依据是用户确认复用现有渠道协议，尚未获得新模型独立响应样本或完成真实付费测试。

## 实际调用链

启动 `initDatabase` → `ensureSiYueTianMinimaxModel` 注册停用模型、按条价格及规格线路。
已有关联只初始化一次；重复启动不覆盖管理员价格、开关或移除的关联。渠道同步发现该 ID 时可以再次建立关联，不覆盖既有价格和线路开关。同名其他产品拒绝覆盖。

网站 `/api/video/validate`、`/api/video/generate`、外部 `/v1/videos` 和批量调度使用 `handleSpecificationGeneration`。规格筛选、互斥及数量校验在预扣前完成；入队后执行前再次核对。视频页面与画布读取同一能力限制。

统一规格服务保存订单和预扣 → 提交占用 → 四月天专用适配器 POST `/v1/videos` → 先保存 `task_id`/`id`、原渠道、原 Key → GET `/v1/videos/{task_id}` → 原结果下载并本地化 → 幂等结算。

上游请求使用 `model`、`prompt`、`duration`、`aspect_ratio`、`image_refs`、`video_refs`、`audio_refs`、`first_frame`、`last_frame`。固定 2K 由模型选择和本地校验保证。本站 API 亦支持 `reference_images`/`image_urls`、`reference_videos`/`video_urls`、`audio_urls`；同类字段不能重复指定。

已确认的失败保留业务码和具体原因并结束订单；无编号的断线或不完整回执不重发。有效任务编号即使伴随网关错误也先保存并查询原任务。查询 404 不当作生成失败。成功回执持久化，保存失败继续保存原结果。轮询窗口结束后后台继续原任务，不因窗口结束转人工核实。

重启恢复由 `resumeSpecificationTasks` 使用原任务与预扣；管理员检查复用相同状态解析。其他渠道的解析和计费没有改用此适配器。

## 使用示例

启用后台模型并按现有权限配置开放给用户后，调用本站：

```json
{
  "model": "minimax-h3-2k",
  "prompt": "海边漫步，海浪声与脚步声",
  "duration": 15,
  "resolution": "2K",
  "aspect_ratio": "16:9"
}
```

首次注册默认停用，不会随部署自动向用户开放。已有管理员售价和模型开关保持不变。
