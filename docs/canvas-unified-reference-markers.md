# 统一素材引用标记（2026-11-08）

根据用户明确要求，画布统一插入、展示 `@ImageN / @VideoN / @AudioN`。绑定仍使用稳定节点 ID，生成前按每种素材实际提交顺序重新编号，不能按画布视觉位置推断编号。

旧画布保存的中文绑定键与 `@图片N / @视频N / @音频N` 继续解析。首次/末尾帧沿用独立帧角色，不伪装成普通参考图。仅显示名称与传输标记变化，不迁移或删除旧画布。

渠道共用映射器同时接受此前的“参考图片N”等文字与新的英文标记；苏打水、LongXia 等已有专属小写协议继续转换，但保留 @。其他直接透传适配器接收画布输出的英文标记，不再由画布统一删除 @。

智赢按用户要求改用英文 @ 格式，并兼容旧中文及从0开始的 ref_N 图片占位符。此项替代 d28af82 的中文输出决策。它是用户要求的格式选择，不能将网页内部接口中文匹配逻辑视作公共 API 英文标记或音色效果已验证的证据。未进行付费生成验证。

FunAI Kling O3 只允许已有前三张元素图的 @Image 标记；第四张起是风格参考，不静默把不支持的 @Image4 当作正常元素绑定。

## 公共提交层收拢

新增 `shared/mediaReferences.ts`，由普通页面回填、渠道兼容入口和服务器提交入口共用引用解析、编号校验和渲染；不再分别维护同一套替换正则。

实际接入路径：
- 网站 `/api/video/generate` 与 `/validate` 的旧直连分支。
- 外部 API 视频创建旧直连分支（包含素材解析完成后的检查）。
- `specificationRequest` 的视频规格入口；画布和批量桥接通过网站/规格路径进入。
- MJNewAPI、NewToken、苏打水、LongXia、HM、四月天以及智赢兼容函数使用公共解析器。其他调用 `mapCanvasReferenceMarkers` 的适配器通过兼容外观复用公共模块。

新式 @ 和旧画布“参考图片N”标记在新提交入口统一为 @ImageN/@VideoN/@AudioN，素材数量不足在提交前明确报错。保持素材原顺序，不去重、删素材或改写人物关系。普通英文名称和邮箱不作为素材引用。

协议差异仍在渠道内：HM 历史 `[ref_1]` 代表第1张，而其他旧图片占位符从0开始；NewToken/四月天保留旧超出素材数量的占位符处理规则；小写标记渠道在最终边界转换。公共入口不抢先改写历史占位符。FunAI 特定模型元素限制、画布稳定节点绑定、上传格式、任务状态及退款逻辑不混入公共引用模块。

恢复继续使用已保存的请求快照，不用新规则重建已受理任务。本次没有改动任务状态、扣退费规则，也没有将各渠道业务错误合并处理。
