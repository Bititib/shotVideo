依据用户提供的《API对接文档(1).txt》第 3、6、7 节：生成参数 `model` 使用 `GET /v1/models` 返回的 `data[].name`；示例名 `seedance-video` 不是固定型号；数字 `id` 不是生成参数。提交 404 的具体文案为 `model not found or inactive` 时，需要核对该请求使用的名称与上游实际开放目录。

用户后续确认模型名称 `2.0B`、参考数量为 9 图 / 0 视频 / 0 音频。保留这一配置，不根据文档示例自动改名、不切换生成模型、不改时长或定价。

2026-10-25 线上核查：渠道 24 当前保存的映射为 `2.0B`；任务 14438 在提交阶段收到上述 404，没有取得上游任务 ID，页面显示已退款。现有“测试连接”查询模型目录时又报“异步视频模型比例或时长配置无效”，此前诊断未显示具体模型及字段。尚未取得目录的真实字段值，不能据此宣称上游停用了型号，也不能把展示名称直接当作新的 API 名称。

此次修正仅增强现有目录诊断：

- 比例或时长校验失败时，保留异常条目的 `name`、`ratio`、`seconds`，并列出目录中的模型名称供核对。只展示这些元数据，使用现有脱敏机制隐藏密钥与链接。
- “测试连接”在目录可解析时核对当前映射是否被目录列出，并将名称写入现有测试结果；目录为空或映射缺失时返回具体问题。目录未列出不能区分上游停用、权限限制或名称不符。
- 测试仅查询 `/v1/models`，不提交生成、不自动同步或修改映射、规格、价格、启停状态和账单。同步仍会拒绝无法确认的规格，避免猜测格式。

验证覆盖实际 `ChannelService.testChannel`：无效规格时保留真实名称和字段、映射与目录不一致、密钥脱敏，以及配置、余额和订单保持不变。真实生成可用性仍需部署后的目录核对与已有授权范围内的生产验证。
