# HUSS BB Seedance 渠道

HUSS 的 `bb-seedance2.5-301010` 映射为本站已有的公开模型
`bb-2.5-301010`，现有用户 API 无需更换模型名。

后台添加渠道时选择 **HUSS（BB Seedance 视频生成）**，填写
`https://www.huss.top` 和 HUSS API Key，然后测试连接并同步模型。

此型号支持 10–30 秒、720p、16:9/9:16/1:1，以及最多 30 张图片、10 段视频、
10 段音频。服务端以 Bearer Key 调用 `/v1/models`、`/v1/videos` 与
`/v1/videos/{id}`；本地上传的参考素材会转为无账号信息的公网临时地址。

保留旧 BlobDraw 渠道用于查询历史任务；验证 HUSS 可用后，在模型规格中启用 HUSS
线路并停用旧 BlobDraw 线路，避免新任务继续流向旧供应商。

## 2026-10-25 成功结果保存与后台恢复修正

依据 HUSS 官方文档 https://www.huss.top/api-docs/ 的视频流程与鉴权说明：GET /v1/videos/{id} 查询原任务；completed + url 下载完整签名链接；下载不附带 API 密钥；storage_status=pending 继续查询。

已确认的代码缺口：
- 后台 recover-upstream 先进入旧视频恢复器，managedSpecification 任务被独立账本保护挡住。现先分派给规格任务执行器，使用原渠道、原任务 ID、原预扣账本；不重新生成、不重新预扣。
- HUSS 视频下载曾落到默认 Authorization 分支。现签名 URL 原样使用，下载不发送 API Key，下载失败保存具体脱敏诊断。
- 保存中状态继续查询；成功但缺少成品地址显示具体诊断；返回不同任务 ID 时不采纳结果。

恢复前校验预扣账本的任务、用户、Token、金额和状态；已退款任务不自动补扣。重复点击复用活动任务。明确任务失败走规格账本幂等退款，查询异常继续查原任务。

验证：8 个相关测试文件 115 项通过，类型检查及生产构建通过。覆盖后台服务入口恢复成功、原账本结算、重复点击、失败退款一次、保存中继续查询、错误账本拦截及签名下载不带密钥。
