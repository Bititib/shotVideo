# KMAI MJ 图片渠道

文档来源：<https://kmai.us.ci/docs>，核对日期：2026-10-18。

仅接入上游 `mj_imagine`。本站调用名为 `kmai-mj-imagine-1k`，显示名为「MJ · 1K（KMAI）」。

## 配置

1. 在「渠道管理」新增渠道，选择「KMAI（MJ 图片）」。
2. Base URL 默认 `https://kmai.us.ci`；填写自己的 KMAI API Key，保存。
3. 点击「测试连接」和「同步模型」。同步仅导入 MJ，不导入该 Key 的其他模型。
4. 在模型管理配置本站按次售价并启用「MJ · 1K（KMAI）」。该价格是一次 MJ 任务的价格，一次返回 4 张图片。在模型路由核对渠道成本和输入限制。

支持带 `/v1` 的 Base URL，保存时自动移除版本后缀。新模型默认停用，不创建售价，不将上游积分直接换算成人民币。重新同步保留管理员配置的价格、限制、开关和已有线路。

## 生成

- 文生图：`POST /v1/images/generations`，JSON 参数为 `model`、`prompt`、`size`。
- 参考图生成：`POST /v1/images/edits`，单图使用 `image`，多图重复 `image[]` 文件字段，最多 6 张；沿用本站参考图校验。
- 仅开放文档确认的 1K 档位；用户确认 MJ 一次原生任务返回 4 张。一次提交，不通过四次调用凑数量。网页和画布固定显示四张，预估和实扣均按一次任务。
- 比例转换为文档中的像素尺寸，例如 16:9 对应 `1280x720`、9:16 对应 `720x1280`。
- 不传 `quality`；上游通过 `size` 的长边判断分辨率档位。
- 完整读取 `data[].url`：返回四个图片地址时分别保存；返回一张 MJ 四宫格合图时，保留原图并按左上、右上、左下、右下拆成四张独立图片，不拉伸或伪造分辨率。上游链接会过期，结果立即转存本站。
- 图片源地址、保存进度和四张结果持久化。下载或保存中断后只恢复原结果；不会再次发起生成或再次扣费。结果不足四张时保留已保存图片，标记待核实，不自动重提。
- 本站图片 API 可省略 `n`；`n=1` 兼容旧客户端，同样表示一次四张任务，`n=4` 也仅提交一次；其他数量拒绝。
- 网页图片生成、画布和本站图片 API 共享统一模型规格、计费和结果保存流程。
- 提交连接中断或缺少结果 URL 时保留生成记录等待核实，不自动重新提交。文档未提供异步图片状态查询协议，不虚构 MJ 轮询接口。
