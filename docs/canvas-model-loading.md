# 画布模型列表加载恢复

日期：2026-10-25。开发基线：`43b1484`。

## 已确认的问题

`GeneratorPanel` 原先通过 `Promise.allSettled` 等待图片和视频两个列表，然后一起写入状态。任一请求挂起都会使另一类模型不可选择；任一失败又会通过共用的 `error` 阻止成功列表自动选中默认模型。图片、视频列表直接调用 `fetch`，没有超时，并缓存尚未结束的 Promise，重新打开面板仍会复用挂起请求。

排查时生产公开列表接口均返回 HTTP 200（图片 4 个、视频 15 个）。这是当时从诊断机器访问的结果，不能证明受影响用户当时的网络或登录态正常。用户最初遇到的具体网络/服务器错误仍需其当时的请求状态确认。

## 实现

- `useCanvasModels` 仅加载当前创作类型。切换类型或账号后忽略旧请求结果，避免旧数据覆盖当前列表。
- 图片、视频、音频目录读取共用本站列表传输层 `modelListRequest`，15 秒限制覆盖响应头和 JSON 读取。超时中止请求，Promise 结束后释放原有并发请求缓存。迟到的结果不能写入成功缓存。
- 继续合并同账号的并发目录读取；强制刷新绕过已完成的短期缓存。超时后手动重试会建立新请求。
- 保留同账号持久化目录供选择，后台更新替换旧列表。切换账号立即隐藏旧列表；音频缓存增加与图片/视频一致的旧账号响应写入保护。
- 显示当前类型及 HTTP 状态、网络失败、超时、JSON/结构异常。成功的空列表继续表示暂无可用模型。
- 聚焦页面或恢复网络时更新当前目录；图片成功加载后继续原有 15 秒和可用时间刷新。失败时不自动循环清除错误，保留手动重试入口。
- 生成入口、上游调用、提交幂等、计费、退款均未改动；缓存不替代服务端权限和价格校验。

## 部署与检查

按现有运维方式，在备份且生成队列空闲后执行：

```sh
cd /opt/shotVideo
git pull --ff-only origin main
docker compose up -d --build app
```

部署完成后先确认画布已保存，再刷新页面加载新前端。在浏览器中将图片模型请求阻断，切换到视频应仍能选择视频模型；阻断当前模型目录后约 15 秒显示超时，恢复网络并重试应能加载。该验证无需提交生成任务。
