# 视频 API 请求重试与持久化去重

更新日期：2026-11-04。

## 调用约定

`POST /v1/videos`、`POST /v1/videos/generations`、`POST /v1/video/generations` 共用本站持久化请求表 `api_video_requests`。前台网站请求、图片、聊天与其他 API 不改变协议。

- `Idempotency-Key` 为可选请求头，1–200 个可见 ASCII 字符。需要跨 POST 的安全重试时，为每个新逻辑任务生成一次并保存；断线、504、SDK 重试等全部复用原键和参数。
- 相同 API Key 和归属用户下，相同键和请求指纹只创建一个本地订单、一次预扣和一次上游生成。重试返回原任务的当前持久状态；明确失败、已退款或成功都不会重新执行生成/扣退款。
- 同键改参数或素材返回 HTTP 409 `idempotency_conflict`。不要为了重试换键；只有主动要求新生成时使用新键。
- 未发送幂等键时，每次 POST 都创建新的持久请求编号，即使参数和素材完全相同；每个新任务分别预扣、生成、结算或退款。不会根据请求内容查找并返回旧失败任务。不传键的客户端必须保存响应任务 ID 并使用 GET 查询，不能把自动重发 POST 当成查询；如需安全重试，应在第一次提交前选择显式键。
- 请求指纹仍保存，用于显式键的参数冲突校验。JSON 对象的键顺序、multipart 随机边界、临时路径和文件名不参与指纹；数组/参考素材的顺序保留。
- 作用域按 API Key 与归属用户隔离，不能用其他 Key 读取或接管此请求。只持久化键和输入的 SHA-256，不存储原始幂等键、提示词、素材或 API 密钥。
- 显式键和历史内容哈希键的记录不自动过期或删除，不以超时、连接断开或服务重启解除保护。原订单仍可通过旧 ID 查询，已删除的原订单返回410。本次不修改历史订单或账本；新的无键 POST 使用独立请求身份，不重新执行历史订单。

## 返回与恢复

新请求的 `id` / `task_id` 使用稳定的 `task_req_...` 字符串，完整保存并使用响应 `status_url` 查询。不要假设它是整数。旧 `task_<本地ID>` 及原任务恢复机制保留。

携带相同显式键的并发请求在订单尚未创建时返回202和同一个稳定请求ID、`Retry-After: 2`。仅查询这个请求；不会主动重放创建请求。进程在订单创建前退出时保留准备状态，阻止不确定的重复发送，需核实原记录。无键的独立 POST 不复用这个准备记录。

创建内容与绑定请求指针在同一 SQLite 事务中；规格任务的预扣也在该事务内。直连任务先原子创建并绑定，再执行原扣费/提交保护。响应丢失、进程退出之后，重试仍通过持久指针找到原内容，恢复只查询已保存的原上游 ID。请求身份不依赖上游是否支持幂等请求头。

响应头 `X-Idempotency-Replayed: true` 表示显式键已复用原请求。无内容记录的前置校验失败保存简短脱敏错误，同一显式键返回原校验结果；没有传键的新 POST 则重新校验。已绑定内容的失败按原账本退款；查询或显式键重试不再进入退款路径。状态查询和稳定ID的成品下载沿用原权限/交付逻辑。

有效但额度用完的 Key 允许识别重试和查询，禁用/过期 Key 仍拒绝；任何新的预扣仍经过原余额检查与原子扣款。

## 实际修改路径与验证

`handleVideoCreation` 身份校验后 → 参数/素材指纹 → 持久声明请求 → 原模型、参数和余额检查 → 内容与请求指针原子绑定 → 原预扣、提交占用、回执保存、轮询与幂等结算。

2026-11-04 按用户要求调整无键请求身份：`claimApiVideoRequest` 为每次无键 POST 使用新的 `request:` 随机标识；显式键仍使用原 `header:` 命名空间。旧 `body:` 内容指纹记录继续保存并支持原 ID 查询，不执行数据库迁移或重写历史账本。网站文档、API_DOC 和模型目录的 cURL/Python 基础示例均改为无需该请求头，另说明可选的重试保护及各任务独立计费。

本次 20 个相关测试文件共 651 项通过，类型检查、生产构建和差异格式检查通过。新增真实 Express 路由与隔离账本测试覆盖三个无键入口的相同参数并发创建、历史内容哈希失败记录不再阻挡新任务、旧退款记录保持不变、显式键并发和终态重放一次结算、参数冲突、提交未知后的原任务恢复、独立新请求的退款不影响原未知任务，以及空/非法显式键拒绝。上游响应均为模拟，没有进行新的生产付费调用或部署。

既有旧初始化测试数据库仍输出 `usage_logs` 缺少 `status` 列的日志警告；新测试使用完整隔离表结构。构建保留现有动态导入与大文件体积警告。部署更新并重启后，新调用约定才会生效。
