# 视频 API 请求重试与持久化去重

更新日期：2026-11-04。

## 调用约定

`POST /v1/videos`、`POST /v1/videos/generations`、`POST /v1/video/generations` 共用本站持久化请求表 `api_video_requests`。前台网站请求、图片、聊天与其他 API 不改变协议。

- 不传请求头也自动防重试：同一 API Key 和归属用户、相同参数与素材的 POST，优先复用仍在准备、排队、生成、待核实或结算未完成的原任务。等待时间、连接断开和服务重启不会释放未知任务的保护。
- 成功后的相同请求在10分钟内复用原任务，保护期从持久完成时间开始，不因重试延长。缺少完成时间的旧路径/历史任务从首次核实成功开始持久计时，保守多保护一段时间。成功保护期结束后的相同 POST 可以创建独立计费的新任务。
- 明确失败且本地退款完成后，允许相同内容新建任务，不再一直返回旧失败。先核对关联预扣账本的 `refunded` 状态；缺账本、待核实、退款未完成或本地信息损坏均保留原任务。没有创建订单的前置校验失败也允许重新校验。
- 自动保护无法识别用户意图：同内容在保护期内会合并，保护期外的 POST 会新建，不能承诺任意延迟的重试永远不重复。参数/素材改变也不属于相同请求。保存任务 ID 并使用 GET 查询；需要持久重试保证时选择显式键。
- `Idempotency-Key` 为可选请求头，1–200 个可见 ASCII 字符。为每个新逻辑任务生成一次并保存；断线、504、SDK 重试等全部复用原键和参数。显式键保留原长期去重语义，不使用10分钟窗口。
- 相同 API Key 和归属用户下，相同显式键和请求指纹只创建一个本地订单、一次预扣和一次上游生成。重试返回原任务的当前持久状态；明确失败、已退款或成功都不会重新执行生成/扣退款。
- 同键改参数或素材返回 HTTP 409 `idempotency_conflict`。不要为了重试换键；只有主动要求新生成时使用新键。
- 主动在保护期内另建同参数任务可使用新显式键；不得用换键重试结果未知的任务。新显式键不与自动请求合并。无键请求会保守检查升级前无法区分模式的历史记录，避免遗漏旧的未知提交。
- 请求指纹用于自动保护及显式键冲突校验。JSON 对象的键顺序、multipart 随机边界、临时路径和文件名不参与指纹；数组/参考素材的顺序保留。字段别名、显式默认值与省略值等不同原始参数不承诺同一指纹。
- 作用域按 API Key 与归属用户隔离，不能用其他 Key 读取或接管此请求。只持久化键和输入的 SHA-256，不存储原始幂等键、提示词、素材或 API 密钥。
- 请求记录不自动删除。自动模式成功窗口结束或失败退款后，只是允许创建新的请求记录，不重开原请求；原任务仍可通过旧 ID 查询，已删除的原订单返回410。本次不修改历史订单、余额或退款流水。

## 返回与恢复

新请求的 `id` / `task_id` 使用稳定的 `task_req_...` 字符串，完整保存并使用响应 `status_url` 查询。不要假设它是整数。旧 `task_<本地ID>` 及原任务恢复机制保留。

自动或显式去重命中的并发请求在订单尚未创建时返回202和同一个稳定请求ID、`Retry-After: 2`。仅查询这个请求；不会主动重放创建请求。进程在订单创建前退出时保留准备状态，阻止不确定的重复发送，需核实原记录。

创建内容与绑定请求指针在同一 SQLite 事务中；规格任务的预扣也在该事务内。直连任务先原子创建并绑定，再执行原扣费/提交保护。响应丢失、进程退出之后，重试仍通过持久指针找到原内容，恢复只查询已保存的原上游 ID。请求身份不依赖上游是否支持幂等请求头。

响应头 `X-Idempotency-Replayed: true` 表示自动或显式复用了原请求。无内容记录的前置校验失败保存简短脱敏错误，同一显式键返回原校验结果；没有传键的新 POST 则重新校验。已绑定内容的失败按原账本退款；命中原请求时只进入查询路径。状态查询和稳定ID的成品下载沿用原权限/交付逻辑。

有效但额度用完的 Key 允许识别重试和查询，禁用/过期 Key 仍拒绝；任何新的预扣仍经过原余额检查与原子扣款。

## 实际修改路径与验证

`handleVideoCreation` 身份校验后 → 参数/素材指纹 → 持久声明请求 → 原模型、参数和余额检查 → 内容与请求指针原子绑定 → 原预扣、提交占用、回执保存、轮询与幂等结算。

本次补充 `claimAutomatic`：用 `BEGIN IMMEDIATE` 原子检查同作用域指纹的持久状态并声明原请求或新请求，避免不同连接并发绕过去重。仍在处理/待核实的原任务优先于其他历史成功记录。仅通过本地订单与预扣账本判断保护，渠道错误含义仍由各适配器解析。

表 `api_video_requests` 通过幂等增列记录 `request_mode` 与 `completed_seen_at` 并新增指纹索引；旧记录标记为 `legacy`，原 ID、key_hash、内容指针、缓存响应和账本不变。旧 `header:` 键仍能精确命中原记录；新显式请求不参与自动合并。迁移检查与增列同样在写事务中执行，支持重复启动。

网站文档、API_DOC 和模型目录 cURL/Python 示例均保留无需该请求头的基本调用，并说明自动保护范围、10分钟成功窗口、明确失败退款后新建和显式键的长期保证。网站、批量队列、图片与聊天调用行为没有改变。

本次21个相关测试文件共671项通过，TypeScript检查、前端生产构建与差异格式检查通过。新增真实路由验证三个 API 别名无键并发只生成/扣费一次、客户端连接中断后直连和规格路由均复用原任务、成功响应丢失后的重试、成功窗口结束后独立新建、明确失败退款后新建，以及未知提交与后台恢复不重发。隔离存储测试验证旧表增列、不同数据库连接和重建存储后的保护、作用域隔离、非滑动成功窗口、旧路径缺少完成时间、退款证据未完成、旧未知任务优先及损坏/已删除订单的保守处理。显式键、其他渠道、批量队列及错误脱敏回归通过。

上游响应均为模拟，未进行新的生产付费调用或部署。现有旧初始化测试数据库仍有 `usage_logs` 缺少 `status` 列的日志警告，构建保留既有动态导入和大文件体积警告。更新服务并重启后自动重试保护才生效，无需手动清库或重写旧订单。
