# 视频 API 请求重试与持久化去重

更新日期：2026-10-31。

## 调用约定

`POST /v1/videos`、`POST /v1/videos/generations`、`POST /v1/video/generations` 共用本站持久化请求表 `api_video_requests`。前台网站请求、图片、聊天与其他 API 不改变协议。

- 推荐请求头 `Idempotency-Key`，1–200 个可见 ASCII 字符。每个新逻辑任务生成一次并保存；断线、504、SDK 重试等全部复用原键和参数。
- 相同 API Key 和归属用户下，相同键和请求指纹只创建一个本地订单、一次预扣和一次上游生成。重试返回原任务的当前持久状态；明确失败、已退款或成功都不会重新执行生成/扣退款。
- 同键改参数或素材返回 HTTP 409 `idempotency_conflict`。不要为了重试换键；只有主动要求新生成时使用新键。
- 旧客户端未发送幂等键时，以 JSON 参数及上传素材内容哈希作为稳定键；相同输入默认返回原任务。主动用同一提示词和素材再生成一次，需要显式新键。JSON 对象的键顺序、multipart 随机边界、临时路径和文件名不参与身份；数组/参考素材的顺序保留。
- 作用域按 API Key 与归属用户隔离，不能用其他 Key 读取或接管此请求。只持久化键和输入的 SHA-256，不存储原始幂等键、提示词、素材或 API 密钥。
- 去重记录不自动过期或删除，不以超时、连接断开或服务重启解除保护。已删除的原订单返回410，不自动再生成。上线前没有记录的新旧请求无法倒推为同一逻辑请求，保护从新版本首次接收请求开始。

## 返回与恢复

新请求的 `id` / `task_id` 使用稳定的 `task_req_...` 字符串，完整保存并使用响应 `status_url` 查询。不要假设它是整数。旧 `task_<本地ID>` 及原任务恢复机制保留。

并发请求在订单尚未创建时返回202和同一个稳定请求ID、`Retry-After: 2`。仅查询这个请求；不会主动重放创建请求。进程在订单创建前退出时保留准备状态，阻止不确定的重复发送，需核实原记录。

创建内容与绑定请求指针在同一 SQLite 事务中；规格任务的预扣也在该事务内。直连任务先原子创建并绑定，再执行原扣费/提交保护。响应丢失、进程退出之后，重试仍通过持久指针找到原内容，恢复只查询已保存的原上游 ID。请求身份不依赖上游是否支持幂等请求头。

响应头 `X-Idempotency-Replayed: true` 表示已复用原请求。无内容记录的前置校验失败保存简短脱敏错误，重复请求返回原校验结果。已绑定内容的失败按原账本退款；重复请求不再进入退款路径。状态查询和稳定ID的成品下载沿用原权限/交付逻辑。

有效但额度用完的 Key 允许识别重试和查询，禁用/过期 Key 仍拒绝；任何新的预扣仍经过原余额检查与原子扣款。

## 实际修改路径与验证

`handleVideoCreation` 身份校验后 → 参数/素材指纹 → 持久声明请求 → 原模型、参数和余额检查 → 内容与请求指针原子绑定 → 原预扣、提交占用、回执保存、轮询与幂等结算。

覆盖规格路由（含 TT480/720/1080 按秒计费）、旧直连视频分支和三个 API 别名。没有改动渠道参数、模型价格/状态、生产订单、已有预扣或上游退款判定。

测试验证并发请求、跨进程数据库连接和重建 store、JSON顺序、上传内容、同键参数冲突、成功/失败/504后重试、已退款重试、已删除订单、不同 Key/用户隔离、事务回滚、旧本地ID兼容及新任务显式换键。未进行生产付费调用或部署。
