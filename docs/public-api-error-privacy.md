# 用户 API 错误信息的渠道隐私修复

本次修复基于 GitHub main 的 `7c3c3ac`，在独立工作区完成，不混入主工作区或旧发布目录的未提交改动。

## 问题与依据

用户提供的 `/v1/videos` 响应在 `error`、`error_message` 和 `progress_text` 中包含 `[上游诊断 funai 提交]`。原有过滤仅挂载视频和图片的部分路由，只处理部分顶层错误字段，且没有移除通用诊断包装中的供应商名称。该错误仅作为展示证据，不据此更改任何上游的受理、重试、计费或退款规则。

## 实际调用链与修改边界

- `server/routes/v1.ts` 的 `handleVideoCreation` 先通过 `claimApiVideoRequest` / `captureApiVideoResponse` 保存逻辑请求身份；重复提交和查询通过 `handleVideoQuery` / `respondPendingApiVideoRequest` 返回原任务或原拒绝。
- 规格请求由 `handleSpecificationGeneration` 创建任务并预扣，`runVideo` 选择线路，适配器负责提交，`acceptVideoSubmission` 保存原任务 ID，`pollVideo` 查询和保存结果，既有账本负责结算或退款。
- `resumeSpecificationTasks`、原任务恢复、网站与批量队列沿用现有执行规则。本次不更改这些规则，也不新增生成请求或生产付费测试。
- 新的 `publicApiErrorResponse` 仅挂载在 `/v1` 路由，复制并投影对外 JSON，覆盖提交、查询、缓存拒绝和调用记录。通用诊断包装、配置的渠道名称及域名、内部路由字段不对外返回；保留可展示原因、错误码、本站任务编号和财务状态。
- 对话 SSE 按完整行解析错误事件，可处理跨网络分块的 UTF-8 字符；只投影错误事件，正常内容、用量事件和结束标记保持语义不变。
- 下载接口原先直接发送纯文本异常，现统一返回经过投影的 JSON 错误；详细交付错误保留在服务端日志，不改变已完成任务及费用。
- `runVideo` 保存每条线路原诊断后再汇总；规格 API 的失败或待核实原因补入 `api_logs.error_message`。管理员接口没有挂载此投影，继续读取后台详细诊断。

## 验证范围

新增测试通过真实 Express 路由、内存数据库和模拟上游，覆盖额度拒绝、重复提交及查询的一次性退款、未知受理不重发不退款、图片提交错误、对话 JSON/SSE 错误、历史任务和旧缓存拒绝、API 历史记录，以及管理员详情保留原诊断。辅助测试覆盖任意渠道诊断包装、嵌套包装、配置名称、错误码、结果链接和正常生成内容。

原 FunAI 集成测试的下载断言仍按五个参数校验，基线实现已传入第六个下载进度回调；本次将断言补齐该回调，没有改动下载实现。
