## 协议与计费依据

- https://www.v6k.top/api/pricing ：逐一核对三个真实 ID、描述、`openai-video` 端点；计费表达式使用 `video_seconds`，使用量单位为 `second`。成本人民币值来自用户截图，不从内部计费系数自行推算人民币售价。
- https://www.v6k.top/docs/openapi-video.json ：1.2.0，沿用 `POST /v1/videos` 的 `model,prompt,seconds,ratio,resolution,images,videos,audios` 字段及 `GET /v1/videos/{id}`、`/content` 下载。
- 有效字符串 `id` 先保存；`unknown` 不是失败。继续使用现有 V6K 查询退避、下载失败保护和事务账本，禁止重复生成或重复扣退款。本次没有新增未经确认的可选参数或重试规则。

## 配置与兼容

- `shared/v6kTt25.ts` 定义真实型号、固定分辨率、素材数量、时长和用户明确指定的售价。新注册的公开 ID 使用真实上游 ID，不新增渠道前缀。
- 已存在的 `ZH-TTseadanco2.5-*` 保留原公开 ID、数字 ID、显示名称、权限、任务记录及既有规格。`v6kTt25SaleId` 将选择结果保存到配置，后续同步继续使用同一产品身份，不把旧订单改名或迁移为新订单。
- `ensureV6kTt25Models` 在启动和同步时应用这一次明确的全局价格要求，将所选三个产品设为 `per_second`，同步相应分辨率价格。`v6k_tt25_requested_second_prices_v1` 保留应用前的价格规则和时间；标记写入后，后续启动/同步不再覆盖管理员的新调整。
- 已有启用产品保留启用状态；首次引入销售规格时保留原渠道已明确关联的同型号映射，以免原本可用的入口因空线路被停用。没有既有产品关联时，新入口和规格默认停用。
- 渠道同步只为当前 Key 的鉴权 `/v1/models` 返回型号建立新线路；公开目录不能授予权限。已有线路的 ID、成本、开关和队列所用标识保持不变，其他渠道不受本次型号绑定影响。
- 不改 `TTTseadanco2.5/720` 的 6.5 元/条，也不改 A/XX 两个入口的 4 元/条；它们不是本次三个产品。个人专属价格、用户权限和已提交任务的价格快照不改。

## 实际调用链与资金保护

1. 网站/画布、外部 API 通过 `handleSpecificationGeneration`；批量队列通过原内部网站入口进入相同规格校验。
2. `specificationRequest`、`routingMismatches`、`selectModelRoutes` 在订单和预扣之前校验数量、时长、分辨率；`quoteVideoRequest`、`PricingService` 按当前入口价格乘生成秒数报价。
3. 订单保存价格快照后沿用原预扣事务或批量账本。`submitSpecificationVideo` 发送真实上游 ID，通过原回执持久化流程保存原任务编号，再查询和下载。
4. 完成/失败使用原预扣金额结算/退款；查询异常保留资金和任务编号。后续售价调整不改变已接受任务的原始价格快照；恢复只查询原任务，不新增付费生成。
