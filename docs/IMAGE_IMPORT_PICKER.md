# 图片逆向：多图分析与逐图查看

2026-11-13。基于 origin/main（0fcfa89），独立工作区 scratch/image-import-picker，分支 codex/image-import-picker。提交前已 fetch 核对，远程 main 与开发基线一致。没有覆盖原目录及 huss-final-publish 的未提交改动。

## 最终交互

复用原 /app/image 页面、原开始逆向按钮和结果区，不新建页面、菜单或多选模式。导入图文后全部图片参与分析，提交前可移除当前图片。每张单独保留状态与结果，右侧缩略图切换只改变显示，不重新请求模型。默认查看第一张；其他图片运行期间可以查看已完成结果。移动端结果区位于输入区下方。

一张失败不影响后续图片；单图上传也进入同一后台执行流程。提交后保留请求编号，刷新后查询原记录和预览，后台继续分析。当前一次最多 100 张，每张输入最多 10MB，不静默截断。图片准备失败时整个分析尚未提交，不部分消费额度。

## 实际调用链

1. 原图片代理 /api/proxy/image 的 mode=list 返回 TikWM 的 images 数组及音乐信息；旧二进制下载调用保留。
2. 页面依次下载并标准化图片，再一次提交 /api/analysis/image-jobs，带稳定 requestId、所选模型和文字排版参数。
3. 后端验证登录、image 功能权限、模型访问与图片真实格式，图片保存到私有 data/image-analysis-inputs；SQLite 事务保存任务和每张图片，并在 usage_logs 中逐张预留次数。
4. 单个后台执行器原子领取 queued 图片，调用原 AIService.analyzeImage（Gemini Files 上传和 generateContent）。明文 Key 不写入任务表。
5. 每张结果独立保存，内容库保存完整 JSON、实际模型及任务索引。次数从 reserved 改为 success；明确失败释放该次预留，重复回调不会重复释放。
6. 页面轮询 GET /api/analysis/image-jobs/:id，预览通过带认证的 /:id/images/:index 获取。记录和图片均按所属用户隔离。
7. 生产启动恢复 queued 图片。重启时正在发送/等待的 running 图片标记结果待核实，不重发。提交断线或无法识别的上游响应同样不自动重发、不释放预留次数。已成功结果遇到内容库写入异常仍保留原结果。

没有修改余额售价、预扣或退款规则；本功能沿用原分析次数规则。原 /analysis/image 单图接口继续保留。

## 协议与错误

沿用现有 TikWM 的 data.images、data.cover、music_info 字段，没有引入新的上游解析服务。Gemini 明确拒绝仅基于相符的 error.code 与标准 error.status，不根据错误文案猜测；范围仅限图片分析调用。诊断保留具体原因并脱敏。
依据：https://ai.google.dev/gemini-api/docs/troubleshooting （2026-11-13 核对，重定向到 Google AI Studio 文档）。没有默认重试付费请求。

## 范围与限制

未部署，未进行真实 TikTok/TikWM 或付费模型联调；远程图片缩略图可能受 CDN 访问规则或过期限制影响。浏览器关闭前需要完成图片准备和任务提交，提交后后台继续。模型同步接口不提供可查询的生成任务 ID，提交结果未知/服务重启中的请求保留待核实，不承诺恢复其丢失响应。
