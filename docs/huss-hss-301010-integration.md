- 官方型号文档：https://www.huss.top/api-docs/models/hss-2.5-301010.md
- 错误处理约定（2026-10-26）：https://www.huss.top/api-docs/video-error-handling.md

## 实际调用链

- 网站 `/api/video/generate`、外部 `/v1/videos` 均先进入 `handleSpecificationGeneration`；批量 worker 通过已认证的内部 `/api/video/generate` 桥接，使用同一规格执行器和原批量账本。
- 同步 `syncHussModels` 按鉴权 `/v1/models` 返回创建型号、原渠道映射和规格路线。新模型默认停用，不创建或覆盖管理员售价。只开放 HSS 的 Key 也可同步，不要求同时开放 BB。
- 规格执行器创建订单并预扣，`runVideo` 占用提交锁；`submitHussVideo` 在发送前通过回调保存原幂等键及规范化请求快照；HTTP 202/200 的 `video_` ID 先写入原订单，再 GET 原 ID。
- 正常查询间隔 12 秒；查询异常保留原任务及详细诊断，遵守 Retry-After。没有 progress 时不显示虚构百分比。上游核对窗口结束仅显示核对说明，不判失败或退款。
- HSS 缺 ID：恢复扫描/管理员恢复沿用原键与完全相同的已保存参数 POST，使用官方同账号幂等保证找回原 ID；不换编号，不访问旧 BB `/videos/submissions`。原快照不完整或键不匹配不发送。
- 旧 BB 仍使用只读提交回执。新 HSS 的参数拒绝结束并通过账本退款；临时受理错误、未知结构、冲突和网络异常保留原请求，不笼统退款。重放阶段的错误不证明先前请求未受理。
- 有效任务失败走原幂等退款路径；成功先下载保存，再结算。下载沿用完整签名 URL，403 等原有回退走 `/v1/videos/{id}/content`，仅初始 HUSS 请求带 Key，重定向不带。下载失败保留原任务，不重新生成。
