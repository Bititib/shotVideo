## 实际调用链

- 网站 `server/routes/video.ts` 校验、预扣后调用 `enqueueHmStudioVideoContent`；实际队列调用共享表单构造器，提交占用在发送前，`readHmSubmission` 解析后持久化任务编号，再 `resumePollForTask` 查询原任务。
- 外部 API `server/routes/v1.ts` 使用同一 HM 队列；其直接提交路径也调用共享表单构造器。本次测试发现直接填写停用模型 ID 可绕过列表隐藏，已在生成入口、预扣前检查注册模型的停用状态。
- 批量服务提交到网站生成入口；重启时未发送的队列恢复调用同一队列，有编号的恢复查询，不靠新生成找回。
- 销售规格 `server/services/specificationAdapters.ts` 也调用共享表单构造器，不需要从客户端传入 nova；nova 的已确认时长、清晰度、素材上限在此再次校验，避免管理规格设置放宽后越过协议限制。
- 结算、明确失败退款和待核实沿用 HM 既有回执分类和幂等账本，本次不改业务状态规则。

## 注册与素材处理

`shared/hmStudioVideo.ts` 为共同定义，seed 注册模型、初始化售价和 HM 渠道映射；网站列表、网页参考素材限制、批量报价、API 输入校验与规格草稿复用该定义。画布在 `shared/canvasVideoReferences.ts` 中增加 nova 的确认能力，不根据模型拼写推断。

新模型首次注册 `isActive=0`，管理员部署后自行启用；重复启动不覆盖已有价格、名称和开关。`30-10-10` 只是内部映射，不注册成第二个公开模型。用户售价与截图上游积分成本分开，不自动换算或将成本写入人民币售价。

nova 参考素材使用既有 HM 的 `omni_reference` / `materials` URL 格式，单张图同样走参考模式；最多 50 项素材全部保留。显式首尾帧模式尚未得到确认，不开放该选项，不把普通参考图偷偷转换为首尾帧。比例字段沿用既有 HM 输入与透传行为，尚未取得 nova 专属比例或素材累计时长限制。

访问代码中的 HM 地址时，网页可打开，但模型文档需要登录；此次能力依据为用户确认，传输协议依据为已有 HM 接入。未进行登录、付费生成、生产数据库修改或部署；不能据模拟测试声称 nova 真实生成成功。
