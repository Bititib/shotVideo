## 2026-10-25：补齐渠道同步到计费编辑的实际流程

此前初始化路径正确，但 `ChannelService.syncModels` 仍走通用同步，直接导入 `30-10-10`，没有关联本站 nova 模型；计费编辑器又只根据已有价格键显示分辨率，导致只有基础单价的规则看不到 720p / 1080p。此前“上游 ID 不注册成第二个公开模型”的结论只覆盖初始化，不覆盖手动同步，这次补齐该遗漏。

- 实际管理入口 `/api/admin/channels/:id/sync-models` 在 HM 响应读取后调用独立 `hmStudioCatalogService`，按已确认映射将上游名称转成本站 ID。`30-10-10 → sd2.5-301010`；Fast/Mini 名称不变，旧 HM 型号使用已有映射，未知型号不猜能力参数或售价。
- 同步去重并以事务保存模型和渠道绑定。新模型默认停用；已有模型的名称、启用状态、管理员价格不覆盖。无定价的新 nova 使用已确认的本站 7 / 12 元，而不是上游返回的成本；明确非法列表、跨供应商公开 ID 冲突不改原配置。
- 旧 `30-10-10` 数据不删除、不重命名，不改历史订单、用户权限与专属定价。若本站新名称缺少价格且旧 HM 记录已有价格，只复制旧价，不补写会改变原报价的分辨率默认价；若两边均已有价格，两份均保留，当前渠道使用本站名称，并在同步反馈中提示管理员核对。其他渠道同名记录不参与复制。
- 计费编辑器从共享 HM 规格读取分辨率，即使价格为空也显示可编辑输入框；兼容旧上游名称，大小写相同的分辨率不重复显示。未填的价格仍沿用既有基础价回退，不在打开/保存窗口时偷偷写入默认价。
- 不改提交、轮询、恢复和账本状态规则。同步后的实际 API 测试确认 `model=30-10-10`、`channel=nova`，使用管理员保存的分辨率价格预扣；模拟明确拒绝后按该金额退款。

上线后需在 HM 渠道重新点一次“同步模型”，再从 `sd2.5-301010` 的“管理价格”进入；新模型仍需管理员确认后启用。若存在旧、新两份定价，以反馈提示核对新模型，不做猜测性合并。

### 实现与调用顺序

1. `publicImageDownload.ts` 使用无 Cookie/Authorization 的 GET，逐跳检查公网 DNS，并把已检查的 IP 固定给实际连接，防止 DNS 重绑定；拒绝内网、保留地址、URL 账号密码和非标准端口。最多 3 次跳转，单图下载/DNS 总超时 30 秒，限制声明大小和实际流量为 20 MiB。不自动重试付费生成。
2. `hmStudioReferenceService.ts` 顺序读取所有图片，验证真实图片内容及完整解码（最多 4000 万像素），不缩放、不转码；把原始字节发布为本站随机、无签名、免登录 `/reference-assets/` URL。单次图片准备预算 90 秒；已有本站公共副本直接读本地校验并复用。错误保留图片序号、HTTP 状态/网络错误码，不输出原始签名 URL 或响应正文。
3. 网站/画布的 `/api/video/generate` 与 API 的 `/v1/videos` 在选定 HM 渠道后、创建生成记录和预扣之前完成此步骤，将结果写入 `reference_images` / `image_urls` 与首尾帧字段。下载失败返回 400，不创建生成订单、不扣费、不发上游生成请求。
4. HM 可选的销售规格同样在预扣前准备图片；网站、API 共用。规格批量 `/validate` 也执行相同预检，不因采用规格入口而绕过。
5. 批量创建在所有创意预检成功后，使用预检返回的本站图片地址更新批次 payload，再执行原事务预扣。队列、自动重试和重启恢复使用持久化公共地址，不再依赖原图床 URL。生成受理结果未知时仍按原机制恢复查询，不重复发送生成请求。
6. 用户显式点击 HM 批次“重试失败项”时，也先检查失败创意图片，再在原事务内更新 payload 和预扣。并发请求沿用操作标识防重复扣费；预检期间批次变化会拒绝本次扣费。不自动扫描、重新生成或重新收费历史失败任务。
7. 非 HM 图片准备仍使用原来的策略；不把其他上游业务状态规则套到 HM。旧的、此前已预扣的未发送任务不会被自动批量迁移。
