# 模型同步范围

同步只刷新本站已接入或管理员明确绑定的型号，不因上游新增型号而自动扩大本站产品范围。

- 纵横 V6K、BB/HUSS、Megaby、FunAI、MJ、海底月、Pidoi 图片等专用同步沿用各自已有的精确型号清单。
- 通用渠道以该渠道的明确模型映射和规格线路为范围。只填写支持型号或填写 `*` 不构成接入。对外 ID 按上游映射匹配，不额外创建原始上游 ID。相同名称也应保存 `对外 ID → 上游 ID` 的映射。
- Haya、LongXia、喵呜、snumom、HM Studio 同时使用代码中已经接入的精确型号定义；名称含 video、image 或 seedance 不能作为接入依据。
- 异步视频只自动接入已确认的 `2.0B`，其他型号须先明确绑定。
- Google 启动发现只刷新已接入的内置型号。已有目录记录不单独构成接入依据，历史模型数据仍保留。

空目录或目录中暂未出现已接入型号时，清理只解除缺少接入依据的旧关联。异常响应不进入清理。通用同步期间管理员修改渠道时拒绝覆盖。V6K 沿用自身的精确清单和归档规则，详见 [V6K 同步范围](V6K_MODEL_SYNC_ALLOWLIST.md)。

不修改现有售价、模型启用开关、订单、任务 ID、余额、预扣和退款记录。新建的明确配置模型仍默认停用。各专用渠道原有产品迁移和缺省价格初始化规则保持不变；同步不触发生成请求。

四月天旧记录仅在明确映射到该渠道的预期上游型号、且没有其他渠道或规格线路占用时原位补齐归属和线路。遇到真实同名冲突或不一致映射时，单个型号回滚并在同步结果中列明，其他已接入型号继续同步。

四月天仅同步该渠道已有的有效模型映射。适配器型号和已保存的规格线路用于核对模型是否已接入，单独存在时不会建立映射。目录使用保存的上游 ID 匹配，不会以原始上游 ID 另建产品。启动和有效目录同步会归档缺少有效映射的旧关联，归档键为 `siyuetian_removed_catalog_bindings_<渠道ID>`。现有渠道重启时不会补回管理员移除的映射，首次创建默认渠道仍会初始化内置已接入型号。已保存的有效映射会保留，清理范围不取决于其启用状态。

四月天渠道的「模型与参数」与 V6K 共用面板。可读取当前 Key 的授权型号、指定本站 API ID、填写固定分辨率、时长、画幅及参考素材限制，并预览实际请求体。保存时核对四月天公开目录的 `openai-video` 接口和当前 Key 的 `/v1/models` 列表，再在同一事务保存模型、规格线路和映射。新模型保持停用，售价及总开关通过关联模型管理。后台预览只构造请求体。

四月天自定义视频沿用 `POST /v1/videos`、原任务查询和结果保存。订单保存提交时的渠道凭据指纹和任务 ID，调整模型映射后仍可查询原任务。目录接口从四月天两个正式域名的公开 `/api/pricing` 核对，生成和恢复使用隔离数据库与模拟上游验证。

其他渠道的移除项归档到 `removed_catalog_bindings_<渠道ID>`，包括关联清单、映射和被解除的规格线路。历史任务继续使用原提交记录中的渠道、Key 和任务 ID。清理无需请求上游，也不修改已保存的产品、售价和结算。
