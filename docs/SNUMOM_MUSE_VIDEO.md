# snumom Muse Video 接入

基线：GitHub main `7b24d75`。核对日期：2026-11-03。

## 依据与参数

- 完整读取 `https://snumom.com/docs/wan-3.0.html`，正文约 193 KB，没有 Muse 专节；再次携带查询参数读取也没有。`/docs/muse-video.html` 为 404。
- `https://snumom.com/api/pricing` 确认 `muse-video`：`720P · 最多8张参考图 · 10秒`，`supported_endpoint_types: ["openai-video"]`，`billing_mode: "per-request"`，上游标价 $0.40/次。
- 用户随后明确确认“跟以往的接口是一样的只是支持参数和时间不同”。据此复用 snumom 已有 JSON 提交/查询协议，不声称公开教程已经列出 Muse 完整参数。
- 固定 720p、10 秒、普通参考图片 0–8 张；沿用现有比例字段及 16:9、9:16、1:1、4:3、3:4、21:9、adaptive。视频/音频/独立首尾帧/文档/智能时长/扩写未开放，不静默忽略或截断。
- 创建 `POST /v1/videos`，Bearer 鉴权，`model:muse-video`、`seconds:"10"`、`size:"720P"`、`aspect_ratio`、`reference_images:[{url,role:reference_image}]`；查询原 `GET /v1/videos/{task_id}`，沿用渠道原结果地址和错误解析。

## 实际调用链和实现

- 网站 `routes/video.ts`：公开名归一 → Muse 时长/清晰度/图片格式与数量校验 → 价格校验 → 原预扣与提交锁 → snumom JSON → 回执立即保存 → 原轮询/结算。
- API `routes/v1.ts`：三条视频 URL 共用处理器；原幂等请求 → 公开名归一 → Muse 校验（含解析上传后的图片总数）→ 原 Token/余额账本 → 原提交/恢复。默认参数补齐 10 秒、720p，不覆盖显式错误参数。
- 规格 `specificationAdapters.ts`：扣费前验证 Muse 素材和对应 snumom 路线；`specificationGenerationService.ts` 强制按次售价。即时完成/失败回执先持久化并优先消费，不因已有终态再查询造成丢结果。Muse 不启用 WAN 按实际秒数补扣的逻辑。
- 批量：原 batch validate → 原账本预扣 → 网站 worker；重复批次 key 不创建新任务或再次收费。
- 重启恢复继续查询原任务，不重新 POST；已有 ID 的查询异常保留原预扣与回执。提交断链/不完整回执维持原待核实保护。明确拒绝或失败由原账本幂等退款。
- `modelInputPresets`、`videoCapabilities`、画布参考素材能力统一为 8 图、0 视频、0 音频、固定 720p/10 秒；网站和模型 API 读取同一能力。
- 启动和同步增加模型及 snumom 绑定，默认停用。没有初始化本站售价，上游 $0.40 不是人民币售价；管理员需配置按次价格再启用。已有价格、启用状态、名称、密钥和映射保留。
