# MJ 图片渠道

接口协议核对日期：2026-10-18。

仅接入上游 `mj_imagine`。本站调用名为 `mj-imagine-1k`，显示名为「MJ · 1K」。

## 配置

1. 在「渠道管理」新增渠道，选择「MJ（图片）」。
2. Base URL 留空使用默认接口，也可填写自定义兼容接口地址；填写自己的 API Key，保存。
3. 点击「测试连接」和「同步模型」。同步仅导入 MJ，不导入该 Key 的其他模型。
4. 在模型管理配置本站按次售价并启用「MJ · 1K」。该价格是一次 MJ 任务的价格，图片数量以实际返回为准。在模型路由核对渠道成本和输入限制。

支持带 `/v1` 的 Base URL，保存时自动移除版本后缀。新模型默认停用，不创建售价，不将上游积分直接换算成人民币。重新同步保留管理员配置的价格、限制、开关和已有线路。

## 生成

- 文生图：`POST /v1/images/generations`，JSON 参数为 `model`、`prompt`、`size`、`async:true`。
- 参考图生成：`POST /v1/images/edits`，multipart 传 `async=true`，单图使用 `image`，多图重复 `image[]` 文件字段，最多 6 张；沿用本站参考图校验。
- 仅开放文档确认的 1K 档位；一次提交，按实际返回的 1–4 个图片地址保存完整原图，预估和实扣均按一次任务。不能根据模型名称、比例或图片数量推断四宫格。
- 比例转换为文档中的像素尺寸，例如 16:9 对应 `1280x720`、9:16 对应 `720x1280`。
- 不传 `quality`；上游通过 `size` 的长边判断分辨率档位。
- 完整读取 `data[].url`：返回几个图片地址就保存几张完整图片，禁止自动裁切、拼接、复制凑数或拉伸。上游链接会过期，结果立即转存本站。
- 图片源地址、保存进度和实际结果持久化。下载或保存中断后只恢复原结果；不会再次发起生成或再次扣费。只在实际返回的图片尚未保存完整时标记待核实，不自动重提。
- 本站图片 API 可省略 `n`；`n=1` 兼容旧客户端，同样表示一次任务，`n=4` 也仅提交一次；其他数量拒绝。
- 网页图片生成、画布和本站图片 API 共享统一模型规格、计费和结果保存流程。
- 上游明确返回积分不足时，页面、画布、生成记录和 API 均提示「上游积分不足，暂时无法生成，请联系管理员补充额度后重试。」；后台保留具体错误和线路尝试记录。未受理任务按原扣款来源退款，结果不确定的任务仍保留待核实提示。
- 画布选中 MJ 图片节点后，节点上方浮现最近一次任务实际返回的横向候选图。悬停或键盘聚焦显示放大预览，点击图片立即设为当前版本并标记“当前”；支持撤销、重做。其他候选、旧版本和节点连线保留，选择不触发生成或扣费。
- 新任务默认使用上游异步协议：保存提交响应的临时 `id`，携带原渠道 Key 调用 `GET /v1/images/{id}`，完成后保存正式 `task_id` 及全部图片地址，再转存原图。查询只发 GET，不重新提交生成。兼容上游直接交付完整图片结果。
- 提交连接中断、缺少查询句柄或完成响应缺少图片时，保留生成记录等待核实，不自动重新提交。旧同步任务的日志 ID 不能直接作为异步查询句柄。

## 异步查询与恢复

临时查询句柄、状态、进度、首次提交时间和固定截止时间保存在 `metadata.mjAsyncImage`，首次 GET 前即落库；此字段不下发普通用户。正式任务 ID 独立保存在 `upstreamTaskId` / `upstreamTaskIds`，异步响应的 `id` 不会混入这些字段。网页和画布沿用现有进度事件；本站图片 API 仍等待本次任务完成后返回图片，不改变客户端调用协议。

正常查询间隔 5 秒，总查询期限为首次提交起 30 分钟，重启或恢复不会重置期限。网络异常、服务繁忙或响应读取失败只重试 GET；连续三次失败先保留待核实，后台每分钟恢复扫描可在原期限内继续查询。服务重启也从已保存的句柄继续。收到明确的 `failed` 才按原扣款来源退款；收到 `completed` 后保存原图并按一次任务结算。

查询返回 404/410 表示句柄不存在或失效，401/402/403 等查询错误也不能证明原任务未生成：保留原任务和费用待核实，不锁定模型、不自动重提、不冒充生成失败退款。未知状态和超过查询期限同样保留待核实。上游进程重启可能让临时句柄失效，因此异步模式也不能保证所有原任务都可自动找回。

转存中断优先恢复已持久保存的原图地址，不重新查询或生成。账单已退款、已结算或在查询/下载期间被管理员处理时，恢复流程停止，不覆盖账单、不追加扣款。

## 网关超时后的原结果恢复

HTTP 504 HTML 错误页只表示网关没有及时交付响应，不能据此判定任务未受理。2026-10-18 的生产记录已出现网关返回 504、原任务耗时 127.6 秒后成功的情况。增加本站请求超时不能消除上游网关的超时。

新任务已携带 `async:true`，收到句柄后不再等待同一个提交请求返回成品。旧版同步超时且未取得结果的任务没有可用的异步查询句柄，不能保证自动找回，也不能自动重提或按未接单退款。临时句柄在上游进程重启后可能失效，不能当作永久日志 ID 或用于下载。

已有待核实 MJ 任务可在「内容管理 → 详情 → 恢复 MJ 原任务图片」操作：核对上游日志的时间、提示词及成功状态，复制该任务的公开图片下载地址。支持原渠道的 `/v1/public/image/<id>` 下载链接，按原任务实际地址数量填写（1–4 个）。网站仅下载并保存完整原结果；全部原图保存后才将原预扣款结算。中断后用同一组地址继续恢复；重复操作不会重新生成或重复扣费。已经退款的任务拒绝走此入口，须另行人工核对费用。

### 积分不足时的行为

上游明确返回积分或余额不足时，只显示明确的失败原因并按原有规则退款，不锁定线路、不冷却、不禁用模型。用户可直接再次提交；系统不会自动重跑失败任务或再次扣费。

MJ 文档明确规定生成提交的 HTTP 402 表示积分不足。按状态码判定，不依赖错误正文中的关键词；空正文、通用 Payment Required、HTML 正文或正文读取中断均按明确拒绝处理。即使响应附带日志 `task_id` 或请求关联 ID，也保留该 ID 并退款，不将本次拒绝误判为已受理或待核实。已受理后的查询错误与生成提交拒绝分开处理，查询错误不作为原任务失败的证明。

模型路由不再因为积分不足、超时、繁忙、鉴权或其他提交错误而自动锁定或冷却；旧版本保存的路由锁定及冷却会自动清除，错误和失败次数保留作诊断。渠道和 Key 也不会因提交错误被自动停用。管理员手动停用的模型、渠道、Key 或线路仍然保持停用。

接口配置或上游额度异常仍会返回明确错误，但不会阻止用户发起新的任务。结果不确定的原任务不自动重复提交、不冒充失败退款。连接测试只验证连接，不代表上游积分充足。

### 持续待核实的原因与处理

2026-10-18 的两笔 MJ 请求均由上游成功生成，耗时分别为 127.6 秒和 127.5 秒，本站却收到上游网关的 HTTP 504。此时同步响应没有交付结果 URL，本站没有依据标记成功或确认未接单退款；「待核实」不是内容审核状态。

取消网站的自动锁定不能修复上游返回的 504。新版已使用异步图片提交与查询，减少等待同步成品导致的网关超时；但提交阶段仍可能无法取得句柄。单独增加本站的请求等待时间，不会把已返回的 504 变成成功结果，启用异步也不会补出旧同步任务缺失的句柄。

新失败记录的 `mjSubmissionDiagnostics` 为管理员保存提交或保存阶段、HTTP 状态、耗时和分类；不记录密钥、图片地址或响应正文，普通用户响应会剔除此字段。已有上游成功结果仍可从原任务下载链接恢复，使用原预扣费用结算。

原生 MJ 分支会在读取响应正文前保存上游返回的任务或请求关联标识；错误页、JSON 读取中断或结果缺少地址时仍保留已取得的标识。请求标识仅供原任务核对，不作为成功受理的证明，不用于猜测查询接口。上游没有返回标识时如实记录缺失，不以下载资源 ID 或本站 ID 冒充。

2026-10-18 根据用户提供的新版文档更正：`/v1/images/generations` 与 `/v1/images/edits` 的同步完成响应明确包含 `created`、`task_id: "evt-…"` 和 `data[].url`。`task_id` 是后台日志对应的长期有效任务 ID，可用于日志检索、报障和 `GET /v1/public/{kind}/{task_id}` 下载。此前“文档未声明 task_id”的结论已过时。此次未进行付费真实请求，文档承诺与真实响应实测仍需区分。

异步模式有两个不同标识：提交响应的 `id` 是仅用于 `GET /v1/images/{id}` 的临时句柄；轮询到 `completed` 后的 `task_id` 才是长期任务 ID。本站分别保存这两个字段；完成响应优先保存 `task_id`，不会被同时返回的临时 `id` 或请求关联 ID 覆盖。

本站两条 MJ 图片流程均支持提取响应中的 `task_id` / `taskId`、`request_id` / `requestId` 及关联响应头；旧同步图片结果兼容 `id`，异步响应的 `id` 仅保存为查询句柄。取得正式任务或请求关联标识后即写入内容记录 `metadata.upstreamTaskId`、`upstreamTaskIds` 和 `upstreamResponses`，早于图片转存。两条流程已用隔离数据库验证成功响应、ID 优先级、仅响应头带 ID、未返回 ID，以及转存前后持久保存。未返回正式 ID 时记录 `response_without_id`，不会编造 ID 或阻止有效图片完成。

后台恢复扫描也覆盖数据库明确标记为 `review`、已持久保存原图地址且原预扣费用仍待结算的 MJ 记录。扫描仅取回原结果，按原用户归属保存，完成后清除旧错误；已有处理中记录继续使用原恢复流程。没有原图地址的 504 任务不会自动重提。已经退款或结算的账单不进入自动恢复；下载过程中账单被人工处理时，也不会覆盖其结算或追加扣款。

## 旧版误裁切记录修复

服务启动及任务恢复扫描时，只对旧版单地址、四个同源裁片且原缓存文件仍存在的已完成记录，将生成结果恢复为一张完整原图；保留旧裁片文件及审计引用，不改费用、不重新生成。原缓存缺失的记录不会凭裁片拼接伪造原图，仍需核对原地址。
