# 生成请求预扣费规则

按后台模型价格，在调用生成服务前预扣余额；余额不足时不调用模型。以下为本次统一的范围：

| 入口 | 处理方式 |
| --- | --- |
| 网站与画布图片生成 | 按请求张数预扣，按成功张数结算，失败部分退款 |
| 旧版图片生成、语音合成 | 请求前预扣，成功结算，失败退款 |
| 开放 API 图片生成、图片编辑 | 请求前预扣，返回有效图片后结算，失败退款 |
| 开放 API 对话 | 按输入估算与最大输出数预扣，收到实际用量后退回差额 |
| 开放 API 视频 | 生成提交前扣款，异步失败继续使用原视频退款流程 |

视频与批量视频沿用原有预扣机制。分析类每日次数配额、模型列表、价格查询、任务状态查询不新增余额收费。

## 用户模型权限与专属售价

在后台「用户管理 → 模型与价格」中，可以独立设置模型权限（继承、单独开通、禁止使用）与专属售价。专属价格沿用模型的计费单位，支持基础单价、Token 输出单价与分辨率价格；填写 0 表示免费，空的分辨率价格使用专属基础单价。保存后的专属价独立于默认售价，清空独立价格或点击「恢复默认」并保存即可移除覆盖。

先按用户名或邮箱的部分关键词搜索客户，再点击对应用户行的「模型与价格」。弹窗显示用户名、邮箱及用户编号，所有修改只保存到所选用户。

管理界面采用表格行内编辑，可按名称、类型及「仅看独立价格」筛选；跨分页的修改保留到统一保存。填写统一单价会替换该行的分辨率独立价；展开分辨率设置后可单独修改，并保留其他分辨率的原正常价格。清空独立价格或点击「恢复默认」即可恢复正常计费。模型权限在单独页签编辑，价格与权限的所有修改统一提交，任一行校验失败时整批回滚。

网站、画布、语音工作流及所属 API Key 按实际调用用户解析价格；系统级 API Key 使用全局价。组织余额作为扣款来源时仍使用调用用户的价格。开通模型不会越过平台模型禁用、会员功能权限、每日配额或 API Key 白名单；价格配置本身也不会授予模型权限。未配置用户覆盖时保留各入口的现有权限行为。

启动时自动新增 `user_model_access`、`user_model_pricing` 与 `user_model_audit`，不改写既有用户或全局价格。覆盖关联模型数据库 ID，模型改名仍保留专属价。配置修改记录操作人和修改前后内容，专属价格带版本号以检测并发编辑。存在专属价时，修改全局计费单位、移走或删除对应全局计费规则会要求先恢复相关用户的默认价格。

管理员接口为 `GET /api/admin/users/:id/models` 和 `PUT /api/admin/users/:id/models/:modelId`，其中 `modelId` 是模型数据库编号。写入包含 `accessMode`、`pricingMode`；专属模式另传 `customPrice`（`billingType`、`inputPrice`、`outputPrice`、`extraParams`）。可传 `expectedRevision`，首次设置为 `null`，后续使用已读取的 `customPrice.revision`。

表格批量保存使用 `PUT /api/admin/users/:id/models`，请求为 `{ "changes": [...] }`，每项另含模型数据库编号 `modelId`，其余字段同单模型接口。批量保存与修改审计处于同一事务中。

生成请求、API 对话与批量任务保存提交时的价格快照，结算和退款不按后来修改的价格重算。已登录模型列表和价格查询禁止公共缓存，浏览器缓存按登录身份隔离。新增测试覆盖用户隔离、免费价、分辨率价、单位校验、管理员权限、API Key 归属、缓存切换、改价后的结算与退款。

## 账务保护

- 预扣与账单写入在同一数据库事务中完成。
- 个人、组织、有限 API Key 均检查当前余额后原子扣款，阻止同时请求造成透支。
- 图片沿用提交时价格；对话预扣与结算使用同一价格快照。
- 新增预扣记录的结算、差额退款、全额退款具有幂等保护；已经结算的记录不会被错误处理分支再次退款。
- 保存原扣款来源；用户切换组织后，退款仍退回原来源。
- API Key 累计消费在退款时同步冲回。

## 待核对情况

`billing_reservations` 保存 `amount`（预扣）、`actual`（已知实际费用）、`state`、`receipt`（原扣款来源）与 `context`（用户、API Key、模型或内容关联信息）。

- `reserved`：任务运行中；也可能是进程中断后未完成结算的记录。
- `settled`：完成结算。
- `refunded`：完成全额退款。
- `review`：上游未返回对话用量，或实际费用超过预扣金额。保持原预扣金额，不将未知用量伪装成已结算费用，也不自动追加扣款。

非流式对话返回 `X-Billing-Status`，对话请求返回 `X-Billing-Reservation` 供定位账单。流式请求的最终账务状态以预扣记录和 API 日志为准。

后台新增“异常账单”入口：超过 24 小时的 `reserved` 列为待核对，不自动退款。管理员核对上游结果和用量后填写实收与依据，事务内原路退回差额，并记录审计日志。旧视频任务继续沿用原任务恢复和退款机制。不要仅凭等待时间就退款，也不要直接重发生成请求。

## 验证

`tests/billingReservation.test.ts` 与 `tests/prechargeRoutes.test.ts` 使用内存数据库和模拟上游，覆盖个人/组织/API Key、并发余额竞争、部分成功、退款幂等、事务回滚、图片/TTS/对话接口预扣顺序和流式用量跨包解析。测试不接触真实账户与付费模型。
