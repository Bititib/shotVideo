# 画布模型菜单定位修复

日期：2026-11-04。

用户最终确认故障入口是画布提示词框中的模型下拉列表，并反馈换浏览器可以使用。线上当前登录账号能读取模型目录，不能据此认定受影响用户原浏览器的缓存、登录态或网络均正常，也不能把缓存当作已经证实的唯一原因。本次未清除任何生产浏览器存储、用户画布或账号配置。

## 复现与原因

线上 Chrome 已复现模型数据存在但菜单越出视口：视口高度958px，模型按钮顶部约818.77px，菜单下缘却到1011.89px，内联bottom为负值，底部选项被画布容器裁剪。

`GeneratorPanel` 首次打开菜单时初始样式为空，浮层先参与普通布局，再由布局效果改为fixed。布局效果在菜单撑高创作面板时测量模型按钮；菜单脱离布局和画布的ResizeObserver重新定位面板后，按钮位置已经改变，而菜单沿用旧坐标。不同窗口尺寸、缩放和内容高度会改变表现。

## 修改

- 模型与参数菜单从首次渲染就使用fixed定位，不先撑高创作面板。
- 观察触发按钮与创作面板尺寸变化，更新打开中的菜单位置；关闭时释放观察器。
- 两个菜单使用各自的元素引用，定位与菜单内操作绑定当前菜单。
- 保留视口边距，避免计算出负的上/下边距。

没有修改模型目录请求协议、用户模型权限、价格、生成提交、恢复或账本。模型请求已有的15秒超时、重试、账号缓存隔离和旧响应保护继续保留。

## 验证

新增回归测试在未修改的GeneratorPanel基线上复现首次测量产生负bottom及面板变化不更新位置两项失败。修复后验证首次定位、模型/参数切换后的搜索与键盘选择、尺寸变化后的重新定位和关闭清理。

真实Chrome使用实际CanvasStudio/GeneratorPanel和本地模拟目录验证，不调用上游生成：1920×863下模型菜单下缘715px、按钮上缘723px；390×844下菜单范围x=18～378、y=336～696，完整位于视口内；1280×720下参数菜单下缘572px、按钮上缘580px。搜索选择第18个模型成功，临时视口设置已恢复。

16个相关测试文件共226项通过，覆盖画布模型加载、缓存隔离、交互、长提示词、自动保存和同步；TypeScript检查、前端生产构建、差异格式检查通过。测试输出一条React act提示但无失败；构建保留动态导入和大文件体积提示。

本地浏览器夹具、测试日志和临时构建目录已清理。生产仍需部署该提交，并刷新原浏览器才能加载新版前端；本次不宣称已解决尚未取得错误证据的原浏览器网络或缓存故障。
