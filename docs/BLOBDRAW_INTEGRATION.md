# BlobDraw 视频模型接入

接口来源：https://www.iblob.cc/#/api-docs

## 配置步骤

1. 在 BlobDraw「账户菜单 → 开放 API」创建密钥，授予 generation:read 和 generation:create。
2. 在本站后台「渠道管理」新建渠道，类型选 **BlobDraw**，地址使用 https://www.iblob.cc/api/v1，在密钥输入框填写 API Key。
3. 保存渠道，点击「测试」和「同步模型」。测试只读取模型，不会创建付费生成任务。
4. 同步自动创建视频模型和统一视频规格，导入上游时长、分辨率、比例、参考图片/视频/音频数量及首尾帧能力。
5. 在后台配置本站用户售价（按条或按秒），再启用对应模型。新模型初始停用；上游积分不会自动转换成人民币售价或成本。
6. 通过现有视频页面、画布或 /v1/videos 调用同步后的本站模型 ID。通用请求字段沿用现有接口：model、prompt、seconds（或 video_length）、resolution、aspect_ratio、reference_images、reference_videos、audio_urls、first_frame、last_frame。

除已识别的 bb-2.5-301010 使用同名本站 ID 外，其余模型使用 blobdraw-{渠道ID}-{上游ID} 作为本站 ID，避免不同账号的数字模型 ID 冲突；发给 BlobDraw 的 model_id 仍为上游实际 ID。重新同步保留管理员已保存的路由、开关、输入限制和售价；上游配置变更后，提交前会再次读取模型并校验，必要时在模型规格管理中更新限制。

## 视频模式和人像处理

- 无参考素材优先选择「文生视频」。
- 图片参考优先选择「图生视频」；视频/音频参考选择模型支持的多模态/参考模式。
- 独立首帧、尾帧、首尾帧分别使用「首帧」「尾帧」「首尾帧」，不能与普通参考素材混用。
- 可以通过 blobdraw_mode（或 mode）显式指定 GET /models 返回的模式原值。
- 模型支持人像处理时默认 portrait；传 face_mode: "native" 使用原图。兼容旧 face_enabled 布尔值，face_mode 优先。
- 上游不支持的组合会明确报错，不会截断素材或静默丢弃。

## 素材

生成前通过 POST /assets 上传文件，再使用返回的整数素材 ID。支持本站 /uploads、/api/uploads、已发布参考素材、Base64 和公网 HTTPS 文件直链；外部链接会下载为文件再上传，上游请求不会直接传链接。外部下载不携带渠道密钥，并检查私网地址、重定向和文件大小。

图片：JPG / PNG / WebP，20 MB。视频：MP4 / WebM / MOV，50 MB。音频：MP3 / WAV / OGG，50 MB。实际内容格式也会检查；GIF 不支持。同一类参考素材不能重复，首尾帧顺序保持不变。

## 任务、费用与恢复

- 使用 X-API-Key 鉴权，POST /generations 创建任务。
- 真正发送生成请求前，持久化 blobdrawIdempotencyKey 和 blobdrawPayload，包含本次上传的素材 ID，不保存密钥。
- GET /generation-tasks/{id} 查询，处理中按 10 秒间隔轮询，使用现有任务记录、计费预扣、失败退款和进程重启恢复流程。
- 提交网络错误、无法解析响应、5xx 或缺失任务编号时保留待核实状态，不自动切换其他线路重复生成；管理员可用保存的原参数和同一幂等键核对原任务。
- 已取得任务编号后只查询原任务；成功后把视频下载到本站保存。相对结果路径基于渠道站点域名解析，下载时不会把渠道密钥发送到 CDN。
- 认证、积分不足或明确限流的提交拒绝，可按现有路由策略切换备用线路。查询错误继续查询，不视为生成失败。
- HTTP 202 只是任务已受理；completed、failed、cancelled 才是终态。
- 本次没有添加任务取消界面或修改现有取消语义。

## 验证

本地协议和隔离数据库集成测试覆盖：鉴权、模型同步、开关保留、参数校验、参考上传与顺序、相对结果地址、应用内计费与任务持久化、提交不确定状态。运行：

    npx vitest run tests/blobDrawAdapter.test.ts tests/blobDrawIntegration.test.ts
    npm run lint
    npm run build

真实账号模型与付费生成需要配置渠道密钥后另行联调。


## 指定模型 bb-2.5-301010

已添加与截图同名的稳定本站模型 ID：`bb-2.5-301010`。同步时只精确识别此名称，实际请求仍发送当前渠道 GET /models 返回的 platform ID；型号中的 301010 不是可推断的 API ID。多个 BlobDraw 渠道可以各自映射到不同的上游 ID，并加入同一模型的线路。它与 HM 的 seedance_v2.5-301010 分开配置和计费。

截图能力草稿：720p；4–30 秒（整数）；16:9 / 9:16 / 1:1 / 4:3 / 3:4 / 21:9；最多 30 张图片、10 个视频、10 段音频；文生、图生、多模态。同步与真实提交均以认证后的模型配置为准，草稿不会覆盖上游更严格的限制。截图的「原生过人脸」不作为开启 portrait 处理的依据。

配置 BlobDraw 渠道密钥后，测试并同步模型，在后台给 bb-2.5-301010 设置本站售价并启用即可使用。不自动套用其他渠道的价格；没有密钥时无法确认账号是否有此模型或完成真实生成验证。

## 上游错误与后台登录

渠道同步的 BlobDraw HTTP 错误通过本站 502 返回，并附带 UPSTREAM_ERROR 和 upstreamStatus；401/403 会明确提示检查上游 API Key 或权限，不会作为本站登录失效而清除管理员登录凭证。本站自身的登录校验仍保留 401。规格列表读取失败会显示加载失败与重试操作，不会以空目录代替失败结果。
