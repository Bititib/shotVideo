# 视频任务取消规则

更新日期：2026-10-25；开发基线：GitHub main `a0b5413`。

## 用户行为

- 只有服务器确认尚未开始发送生成请求的任务才显示“取消”。已受理、正在提交、提交结果未知、查询异常、保存结果中的任务均不能取消。
- 页面使用服务器在任务列表、详情和 SSE 事件中返回的 `canCancel`，不根据进度、是否拿到数据库 ID 或提示文字猜测受理状态。未知权限默认不显示取消。
- 点击取消后等待服务器确认；成功后才关闭进度连接并移除当前卡片。失败时保留任务和进度连接，继续查询原任务。
- 进行中的视频不能通过删除内容接口绕过取消检查。终态记录仍可按原权限删除。

## 实际执行路径

网站入口 `/api/video/generate` 分别进入旧版视频执行路径或 `handleSpecificationGeneration` 的规格路由；HM 任务使用 `hmStudioQueue`。创建记录和预扣先完成，`claimVideoSubmission` 在发送生成请求前写入持久提交标记，`acceptVideoSubmission` 保存原上游回执；后续沿原任务轮询、下载、结算或恢复。

`POST /api/contents/:id/cancel` 使用登录用户身份。它在 SQLite immediate 事务内重新读取任务、核对归属和持久回执，要求 `videoSubmissionState=preparing`，且没有提交开始标记、任务 ID、受理编号、审核或终态证据。数据库 ID 本身不表示上游已受理。

取消只复用原有账本：旧路径使用 `finalizeReservedContent`，规格路由使用已有失败结算入口。预扣必须处于 reserved 状态并明确关联当前用户和任务；退款与任务终态在同一事务内提交。退款失败则整体回滚。重复取消不会重复退款，取消成功的记录以现有 failed 终态及 `cancelledBeforeSubmission` 标记保留，防止队列和恢复扫描再次提交。

事务成功后移除 HM 尚未启动的队列节点；已进入执行函数但尚未发送的任务仍由提交占用检查阻止发送。批量生成继续使用现有 cancel-pending 入口，只处理 queued / retry_wait 项，不改变 running 项或原任务计费。

## 验证与范围

- 新增 15 项测试：实际网站普通/HM 规格队列取消、取消后恢复不重发、并发取消退款一次、提交中/已受理/结果未知拒绝取消、独立回执保护、退款异常回滚、归属检查、已提交原任务继续完成，以及页面恢复和 SSE 按服务器权限控制取消。
- 关联回归运行 16 个测试文件，共 271 项通过、5 项失败。5 项失败均来自 `zonghengVideoGrouping.test.tsx` 中旧 ZH 模型名称/素材限制断言；独立的未修改 `a0b5413` 副本复现相同 5 项失败（该文件其余 3 项通过），本次未改动这些模型规则。
- TypeScript 检查通过；前端生产构建通过，保留既有的大文件体积警告。
- 仅使用隔离内存账本和模拟上游，没有真实付费生成、生产数据库操作或生产部署。主目录和原发布目录的其他未提交改动未移入本修复。
