# 灵序 AI 视频插件 1.1.3：排队与进度

原来缺少百分比会被外部 API 归为 queued，插件又将 queued + 0 显示成“排队中 0%”，并忽略 progress_text。此次修复只改变状态展示与公开响应投影，不改变提交、计费、重试或结果归档策略。

## 对外响应

查询接口增加 `phase`、`queue_scope`、`progress_known`。兼容旧客户端，`progress` 和 `progress_pct` 仍为数值；新客户端必须结合 `progress_known`，不能把默认 0 当真实进度。

| phase | 意义 |
| --- | --- |
| website_queue | 本网站队列，queue_scope=website |
| upstream_queue | 上游明确返回 queued/pending，queue_scope=upstream |
| submitting | 网站正在准备或提交 |
| accepted | 已保存受理证据，等待明确阶段 |
| generating | 生成中，是否显示百分比取决于 progress_known |
| saving | 上游已完成，网站尚在保存结果 |
| waiting | 暂无足够证据判断阶段 |
| review | 原任务待核实，继续查询，不新建任务 |
| completed / failed | 网站已确认终态 |

只有网站队列才附带本地队列位置；不再给缺失位置默认填 1、缺失限制默认填 10。上游排队不复用旧的网站队列位置。公开阶段字段不包含渠道名称、上游 ID 或密钥，原隐私过滤仍然生效。

实际路径包括直接提交、HM 队列提交、规格路由异步提交和 GET /v1/videos/:id。缺少进度不会再单独触发 queued；提交成功回执也不直接等同于上游排队。状态投影不改持久化账本和恢复调度。

## 插件显示与兼容

分镜按钮显示短状态、可确认的百分比；详细 progress_text/message 写入任务记录和 progress_callback 的 tooltip，避免长文字挤坏按钮。展开任务记录时每 5 秒读取本地记录；不新增收费请求。恢复、失败、查询异常仍查询原任务。

字字动画在调用插件前就显示本地“排队中”，此阶段不开放插件回调。插件不能重命名宿主原始按钮；面板说明本地队列的含义，接手时立即显示“准备提交”。不能仅凭旧宿主的 0% 判断是否已提交。

旧网站缺少 phase 时保守显示“等待状态确认”；处理态继续可用，未知 0% 隐藏。完整排队区分需要部署本次网站代码。

## 验证与发布

- 真实本地 HTTP 查询入口覆盖网站队列、上游队列、受理、真实 0、未知进度、非法百分比、保存、待核实和终态，经过鉴权与公开脱敏中间件。
- 模拟生成到下载回填路径验证只提交一次，查询异常与待核实不中断原任务追踪。
- 面板在 280 / 390 / 760px 检查自动刷新、文字转义、模型参数保持及无横向溢出。
- ZIP 只含 main.py、updater.py、info.json、ui/index.html、使用说明.txt，不含配置或任务数据库。
- 未创建真实收费生成任务，未修改其他用户电脑，也未改宿主程序。

部署网站后，下载页和远程清单才会提供 1.1.3。旧用户安装后须保存作品、彻底退出并重新打开字字动画。
