# HUSS BB 渠道A替换记录

核对日期：2026-11-01。

## 协议依据

- https://www.huss.top/api-docs/unified-capabilities.json
- https://www.huss.top/api-docs/unified-video.md
- https://www.huss.top/api-docs/video-error-handling.md

精确上游 ID：`bb-2.5-301010-渠道A`。`channel-a.md` 当前描述的是 ht 型号，不用于推定 BB 能力。
BB 能力：720p、5–30 秒整数，比例 16:9/9:16/1:1/4:3/3:4/21:9/adaptive；图片30、视频10、音频10，合计30。参考视频总长15秒、参考音频总长30秒由上游校验，不静默裁剪。官方提示词上限20000 Unicode字符；依用户既有要求不另加本地长度拦截，不截断提示词。

## 映射与升级

`bb-2.5-301010` 与 `hss-2.5-301010` 均映射至新渠道A，保留已有显示名、售价、权限和启用开关。
启动迁移仅修改既有 HUSS 渠道中关联这两个公开模型的配置和规格，不修改历史 contents、原上游模型、请求快照、编号或账本。迁移只执行一次；管理员后续修改不会被每次重启覆盖。
同步只选新渠道A与已接入 Midjourney，不重新引入旧 BB 或 HSS 渠道B。新同步且不存在的模型仍默认停用，已有启用状态及价格不覆盖。未开放渠道A的密钥需要上游开通权限。

## 调用链与恢复

网站、外部 API、批量请求进入现有视频请求/规格路由，使用原订单预扣和提交占用机制。`specificationAdapters.submitSpecificationVideo` 传真实上游 ID；`submitHussVideo` 提交前记录原 UUID 幂等键和 JSON快照。
新请求 POST `/v1/videos`，显式 `X-Huss-Video-API: unified-v1`，三类素材字段为 reference_images/reference_videos/reference_audios。保存响应的不透明 id，不限制前缀。已有 ID 只 GET `/v1/videos/{id}`；首次响应丢失按统一协议使用原键和完全相同 JSON 找回，不能换键或换型号。旧任务仍按原快照协议恢复。
明确拒绝经适配器进入原失败账本；即时 failed 回执先保存 ID，再处理一次退款，无需等待再次查询。查询HTTP错误不是任务终态。受理不确定或证据冲突不能推定退款。
completed 先持久化成功交付证据，然后下载；所有 HUSS 视频优先通过原 `/content` 获取新下载地址，跳转不带API Key。临时下载失败保留成功证据和预扣，按原编号退避恢复；重启扫描继续，不发第二次生成。保存成功清除保存错误与交付中标识，原账本结算。上游明确410成品过期转交付核实，不伪造成功或自动重新生成。
