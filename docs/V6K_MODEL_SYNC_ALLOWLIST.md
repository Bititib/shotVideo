# V6K 只同步已指定接入型号

更新日期：2026-10-31。本记录覆盖旧版“导入 Key 返回的所有可识别视频型号”和“用本次目录替换渠道模型列表”的行为。

## 自动新增范围

`shared/v6kSyncModels.ts` 是精确匹配的同步白名单：

| 鉴权目录中的上游 ID | 本站入口 |
| --- | --- |
| `TTTseadanco2.5/720` | 原按条入口 |
| `Asedanco2.0`、`Asedanco2.05` | `zh-seedance.2.0`，两条线路 |
| `XXsedanco2.0` | XX 独立入口 |
| `TTseadanco2.5-480` | TT 480P 入口 |
| `TTseadanco2.5-720` | TT 720P 入口 |
| `TTseadanco2.5-1080` | TT 1080P 入口 |

共 7 个上游 ID、6 个销售入口。TT 已有的公开 ID 仍按原身份使用；不改名或迁移旧任务。已退役旧站的 KK/QQ 型号不会重新导入；其他渠道的同步规则不变。

## 同步行为

1. 后台渠道“同步模型” → `POST /api/channels/:id/sync-models` → `ChannelService.syncModels` → `syncV6kVideoModels`。
2. 沿用 V6K `GET /v1/models` 的 Bearer 鉴权、原渠道地址和 Key，只处理“白名单 ∩ 当前 Key 返回 ID”。依据为 https://www.v6k.top/docs/openapi-video.json 中的模型查询说明及已验证目录格式。型号名称相似、视频标签、公开广场展示都不能扩展名单；运行时不再请求公开 `/api/pricing` 分类。
3. 仅新增缺少的白名单模型、渠道关联及执行线路。新模型默认停用；已有模型的价格、计费单位、分辨率价格、显示名称、描述、启用状态、规格限制，以及线路 ID、优先级、成本和开关保留。
4. 渠道模型列表和映射改为合并，原有关联、手动映射和非白名单历史型号保留。不自动清理先前已经导入的其他型号。目录暂时不含某个已有型号时，也不删除其原线路或强制停用。
5. 没有匹配项时返回 0 和说明，不写配置；查询失败、响应格式错误时不写配置。取回目录期间渠道 Key、地址或类型变化，则中止同步，避免把旧身份的查询结果写入新配置。
6. TT 默认价格初始化改为只填缺失规则，包括旧库尚无旧版价格迁移标记时也不覆盖既有价格。已存在的 `v6k_tt25_requested_second_prices_v1` 记录继续保留；更新和同步不会再次套用先前的售价调整。

## 任务与资金

本次同步不写 `contents`、原任务回执、预扣账本、批量队列、用户余额、Token 用量或个人专属价格/权限，不发起生成请求，也不执行结算或退款。已有模型 ID、渠道关联和路线对象保持不变，让网站/API 的原任务恢复和批量队列仍可使用原有身份、编号及价格快照。

部署重建会短暂重新创建应用容器；已有上游任务保留在数据库，仍由原恢复逻辑查询，不能将部署描述成完全没有连接中断。
