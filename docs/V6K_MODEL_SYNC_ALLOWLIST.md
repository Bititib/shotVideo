## 同步行为

1. 后台渠道“同步模型” → `POST /api/channels/:id/sync-models` → `ChannelService.syncModels` → `syncV6kVideoModels`。
2. 沿用 V6K `GET /v1/models` 的 Bearer 鉴权、原渠道地址和 Key，只处理“白名单 ∩ 当前 Key 返回 ID”。依据为 https://www.v6k.top/docs/openapi-video.json 中的模型查询说明及已验证目录格式。型号名称相似、视频标签、公开广场展示都不能扩展名单；运行时不再请求公开 `/api/pricing` 分类。
3. 仅新增缺少的白名单模型、渠道关联及执行线路。新模型默认停用；已有模型的价格、计费单位、分辨率价格、显示名称、描述、启用状态、规格限制，以及线路 ID、优先级、成本和开关保留。
4. 渠道合并后只保留真实上游 ID 属于精确白名单的关联和执行线路，包括映射到已接入型号的自定义入口、BB/HSS、已关闭的合法线路。目录暂时不含某个已接入型号时，不因目录缺席删除其原线路或强制停用。非白名单历史关联则先归档再解除，不再出现在该渠道的模型管理列表。
5. 没有匹配项时返回 0 和说明，不写配置；查询失败、响应格式错误时不写配置。取回目录期间渠道 Key、地址或类型变化，则中止同步，避免把旧身份的查询结果写入新配置。
6. TT 默认价格初始化改为只填缺失规则，包括旧库尚无旧版价格迁移标记时也不覆盖既有价格。已存在的 `v6k_tt25_requested_second_prices_v1` 记录继续保留；更新和同步不会再次套用先前的售价调整。

## 任务与资金

本次同步不写 `contents`、原任务回执、预扣账本、批量队列、用户余额、Token 用量或个人专属价格/权限，不发起生成请求，也不执行结算或退款。全局模型记录、数值 ID、显示名称、价格和启用状态均不删除或改写；仅解除 V6K 渠道中未接入型号的支持列表、映射和规格线路。其他渠道不受影响。

启动在产品初始化完成后也执行同一清理，因此更新并重建后即可去除旧关联，不必逐个手动删除。原支持列表、映射和移除线路存入数据库 `v6k_unapproved_binding_archive`，不包含渠道密钥；重复启动或同步没有新变化时不重复归档。配置格式异常时整个清理事务回滚。

已接单任务依靠原渠道、Key、任务 ID 和价格快照查询恢复，不依赖渠道当前的销售支持列表；即使是已经解除关联的历史型号，也继续完成原任务或按原任务明确失败结果一次退款。没有受理的新请求不能借历史型号继续在该渠道生成。未接入型号的全局历史模型记录仍可能在“所有渠道”视图出现，本次不删除这些记录。

部署重建会短暂重新创建应用容器；已有上游任务保留在数据库，仍由原恢复逻辑查询，不能将部署描述成完全没有连接中断。
